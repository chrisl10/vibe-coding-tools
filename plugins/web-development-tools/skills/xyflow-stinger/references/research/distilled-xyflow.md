## 5. State ownership: the biggest React and Svelte divergence

| Concern | React Flow | Svelte Flow | Source |
|---|---|---|---|
| Declaring state | `useState`, or `useNodesState`/`useEdgesState` returning `[nodes, setNodes, onNodesChange]` (documented as a prototyping convenience: "in practice you may want to use a more sophisticated state management solution") [raw/react-flow--api--use-nodes-state.md] | `let nodes = $state.raw([...])`, `let edges = $state.raw([...])` | [raw/react-flow--guide--adding-interactivity.md], [raw/svelte-flow--docs--installation.md] |
| Wiring changes back | `onNodesChange` + `applyNodeChanges`, `onEdgesChange` + `applyEdgeChanges`, `onConnect` + `addEdge`, handlers in `useCallback` with functional setters | Two-way `bind:nodes` and `bind:edges`; the component writes interactions back | [raw/react-flow--guide--adding-interactivity.md], [raw/svelte-flow--guide--building-a-flow.md] |
| Why raw state | not applicable | `$state.raw` avoids deep per-property reactivity overhead; plain `$state` is described as a potential bottleneck | [raw/svelte-flow--guide--building-a-flow.md], [raw/svelte-flow--guide--migrate-to-v1.md] |
| Immutability | Mutating node objects in setters is prohibited in v12; return new objects | Direct mutation (`nodes[0].position.x = 100`) no longer triggers updates; reassign with `map` and spread, or `updateNode` | [raw/react-flow--guide--migrate-to-v12.md], [raw/svelte-flow--guide--migrate-to-v1.md] |
| Updating data from inside a node | `updateNodeData(id, partialOrFn, { replace? })` on `useReactFlow()` (merges by default), or a store action creating a new node and new `data` object ("create a new object here, to inform React Flow") | `updateNodeData()` from `useSvelteFlow()` | [raw/react-flow--api--react-flow-instance.md], [raw/react-flow--guide--state-management.md], [raw/svelte-flow--guide--custom-nodes.md] |
| External store | Zustand recommended (React Flow uses it internally); Redux, Recoil, Jotai viable | Function bindings with getter and setter pairs for external stores | [raw/react-flow--guide--state-management.md], [raw/svelte-flow--guide--migrate-to-v1.md] |
| Hook return shape | Plain values (for example `useNodeConnections` returns an array) | Objects with `.current` (plus `update`/`set` on `useNodes`) | [raw/react-flow--api--use-node-connections.md], [raw/svelte-flow--api--use-nodes.md] |
| Viewport binding | not captured | `$state<Viewport>` plus `bind:viewport` | [raw/svelte-flow--guide--migrate-to-v1.md] |
| Persisting | `toObject()` on the instance returns nodes, edges, viewport; or persist local nodes and edges state; saving is an explicit action | `toObject()` on `useSvelteFlow()` | [raw/react-flow--example--save-and-restore.md], [raw/svelte-flow--api--use-svelte-flow.md] |

## 6. Providers and hooks

| Fact | Detail | Source |
|---|---|---|
| React provider cases | `useNodes()` returns the current nodes array (the provider example maps over it). Explicit `<ReactFlowProvider>` needed when hooks run outside the `<ReactFlow>` subtree, for each of multiple flows on a page, and outside a router to persist state across routes. `<ReactFlow>` provides context to its own subtree | [raw/react-flow--api--react-flow-provider.md] |
| Svelte provider cases | Same three rules for `<SvelteFlowProvider>`; missing context raises "Could not find a Svelte Flow context" | [raw/svelte-flow--api--svelte-flow-provider.md], [raw/svelte-flow--docs--common-errors.md] |
| `useReactFlow` | Returns a `ReactFlowInstance`; does not re-render on state change; query on demand. Methods include `updateNode`, `updateNodeData`, `updateEdge`, `updateEdgeData`, `setNodes`, `addNodes`, `getNodes`, `getEdges`, `getInternalNode`, `screenToFlowPosition`, `fitView` (returns a Promise), `toObject`, `deleteElements` (returns a Promise), `getIntersectingNodes` | [raw/react-flow--api--use-react-flow.md], [raw/react-flow--api--react-flow-instance.md] |
| `useSvelteFlow` | Viewport (zoom, setCenter, setViewport, fitView, fitBounds), nodes (getNode, getInternalNode, updateNode, updateNodeData), edges, intersections, `screenToFlowPosition`/`flowToScreenPosition`, `deleteElements`, `toObject` | [raw/svelte-flow--api--use-svelte-flow.md] |
| `useStore` | Escape hatch over internal state; React version is Zustand's selector hook with optional equality function; use dedicated hooks first | [raw/react-flow--api--use-store.md], [raw/svelte-flow--api--use-store.md] |
| `useNodesData` | Single id returns `{id, type, data} or null`; array returns an array; subscribes only to data | [raw/react-flow--api--use-nodes-data.md], [raw/svelte-flow--api--use-nodes-data.md] |
| `useNodeConnections` | Current hook; params `handleType`, `handleId`, `nodeId` (optional inside a custom node) | [raw/react-flow--api--use-node-connections.md], [raw/svelte-flow--api--use-node-connections.md] |
| `useHandleConnections` | Deprecated in React Flow "in favor of the more capable useNodeConnections"; params were `type`/`id` | [raw/react-flow--api--use-handle-connections.md] |
| `useUpdateNodeInternals` | Call after programmatically adding, removing, or moving handles; accepts an id (Svelte also an array or nothing) | [raw/react-flow--api--use-update-node-internals.md], [raw/svelte-flow--api--use-update-node-internals.md] |

## 7. Custom nodes, handles, and edges

| Fact | Detail | Source |
|---|---|---|
| Stable `nodeTypes` | Define `nodeTypes` (and `edgeTypes`) outside the component, or memoize; Svelte warns when a new object is created each render | [raw/react-flow--guide--custom-nodes.md], [raw/svelte-flow--docs--common-errors.md] |
| Type key mismatch | Unknown `type` falls back to `default` with a warning; keys are matched exactly | [raw/svelte-flow--docs--common-errors.md] |
| Svelte node props | `let { id, data }: NodeProps = $props()` replaces `export let` and `$$Props`; a custom node is an ordinary Svelte component registered in `nodeTypes` | [raw/svelte-flow--guide--custom-nodes.md], [raw/svelte-flow--guide--migrate-to-v1.md], [raw/svelte-flow--example--custom-node.md] |
| Utility classes | `nodrag` (no drag, no selection), `nopan`, `nowheel`; Svelte allows renaming via `noDragClass`, `noPanClass`, `noWheelClass` | [raw/react-flow--guide--custom-nodes.md], [raw/svelte-flow--docs--utility-classes.md] |
| Multiple handles | Each extra handle of the same type needs a unique `id`; edges select it with `sourceHandle`/`targetHandle` | [raw/react-flow--guide--handles.md], [raw/svelte-flow--guide--handles.md] |
| Hiding handles | Use `visibility: hidden` or `opacity: 0`, never `display: none` (breaks measurement) | same |
| Handle outside node | "Handle: No node id found" when `<Handle>` renders outside a custom node | [raw/svelte-flow--docs--common-errors.md] |
| Connection mode | `ConnectionMode.Strict` (default, source to target) or `ConnectionMode.Loose` (any handle to any handle), set on the flow | [raw/react-flow--api--connection-mode.md], [raw/svelte-flow--api--svelte-flow-component.md] |
| Validation | React: `isValidConnection: (edge: Edge \| Connection) => boolean` on the flow. Svelte: `isValidConnection` prop typed `IsValidConnection<Edge>` (parameter shape not captured) [raw/svelte-flow--api--connection-props.md]; a node needs at least one `Handle` to be connectable. Handler types: `OnNodesChange<NodeType>` receives `NodeChange<NodeType>[]`; `OnConnect` receives a `Connection` | [raw/react-flow--example--validation-isvalidconnection.md], [raw/react-flow--api--callback-types.md] |
| Custom edge | Component receives `id`, `sourceX`, `sourceY`, `targetX`, `targetY`; compute with `getBezierPath`, `getSimpleBezierPath`, `getSmoothStepPath`, `getStraightPath`; render `<BaseEdge id path />`; register in `edgeTypes` | [raw/react-flow--guide--custom-edges.md], [raw/svelte-flow--guide--custom-edges.md] |
| Edge label portal | React: `<EdgeLabelRenderer>` with an absolutely positioned div translated to `labelX`/`labelY`; it has no pointer events by default, so interactive labels set `pointerEvents: 'all'` [raw/react-flow--api--edge-label-renderer.md]. Svelte 1.x: `<EdgeLabel x y selectEdgeOnClick>`, renamed from `EdgeLabelRenderer`; interactive children need `nodrag nopan` | [raw/svelte-flow--guide--edge-labels.md], [raw/svelte-flow--guide--migrate-to-v1.md] |
| Add node on edge drop | Compose `onconnectstart`/`onconnectend` with `screenToFlowPosition`; no dedicated API | [raw/svelte-flow--example--add-node-on-edge-drop.md] |

## 10. Layout and sub flows

| Fact | Detail | Source |
|---|---|---|
| No built-in auto layout | Neither library bundles a layout engine; four documented choices: Dagre, d3-hierarchy, d3-force, ELK (elkjs) | [raw/react-flow--guide--layouting-overview.md], [raw/svelte-flow--guide--layouting-overview.md] |
| Dagre | Simple directed-graph layout, minimal configuration; limitations laying out sub flows connected outside the sub flow; supports dynamic node sizes | [raw/react-flow--guide--layouting-overview.md] |
| d3-hierarchy | Single-root trees; assigns the same width and height to all nodes | [raw/react-flow--guide--layouting-overview.md], [raw/svelte-flow--guide--layouting-overview.md] |
| d3-force | Iterative physics simulation across renders; rectangular nodes need custom collision | same |
| ELK | Most configurable and most complicated; asynchronous (Promise); supports dynamic sizing, sub-flow layouts, edge routing | same |
| Measured sizes | Layout needs real rendered sizes, read from `node.measured` after measurement | [raw/react-flow--guide--layouting-overview.md], [raw/react-flow--guide--migrate-to-v12.md], [raw/svelte-flow--guide--layouting-overview.md] |
| Static Dagre example | Official Dagre example lays out once; "If the nodes or edges in the graph change, the layout won't recalculate!" The reusable `useAutoLayout` example is Pro-gated, so a live re-layout loop in this Stinger is a derived design | [raw/react-flow--example--dagre-auto-layout.md] |
| Edge routing around nodes | `react-flow-smart-edge` and `libavoid-js` are named as options | [raw/react-flow--guide--layouting-overview.md] |
| `@dagrejs/dagre` | 3.1.1, published 2026-08-08, MIT; the unscoped `dagre` is frozen at 0.8.5 (version published 2019-12-03) | [raw/dagre--registry--versions.md] |
| dagre API | `new dagre.graphlib.Graph()`, `setGraph({ rankdir, nodesep, ranksep })`, `setDefaultEdgeLabel`, `setNode(id, { width, height })`, `setEdge`, `dagre.layout(g)`; output `x`/`y` are node centers, read with graphlib `g.node(id)` (returns `undefined` when absent); `g.hasNode(id)` checks membership; `rankdir` is `TB`, `BT`, `LR`, or `RL`; ES module import shape not documented on the wiki | [raw/dagre--docs--basic-usage.md], [raw/dagre--docs--graphlib-api.md] |
| `elkjs` | 0.12.0, published 2026-07-17, license `EPL-2.0 OR GPL-3.0-or-later` (copyleft, unlike xyflow's MIT) | [raw/elkjs--registry--versions.md] |
| d3 layout modules | `d3-hierarchy` 3.1.2 (published 2022-04-02) and `d3-force` 3.0.0 (published 2021-06-05), ISC; npm package metadata last modified 2022-06-14 | [raw/d3--registry--hierarchy.md], [raw/d3--registry--force.md] |
| Sub flows | Any node type can be a parent; the built-in `group` type (transparent background, border) is common for containers [raw/svelte-flow--guide--sub-flows.md]. Set child `parentId`; child `position` is relative to the parent's top-left; parents must precede children in the array; `extent: 'parent'` constrains dragging and needs a valid parent with dimensions | [raw/react-flow--guide--sub-flows.md], [raw/svelte-flow--guide--sub-flows.md], [raw/svelte-flow--docs--common-errors.md] |
| Sub flow edge z-index | Edges on parented nodes render above siblings by default; tune with `defaultEdgeOptions={{ zIndex: 1 }}` | [raw/react-flow--guide--sub-flows.md] |

## 12. SSR and frameworks

| Fact | Detail | Source |
|---|---|---|
| Node sizes on the server | Provide `width`/`height` (fixed) or `initialWidth`/`initialHeight` (may change after hydration) | [raw/react-flow--guide--ssr-ssg-configuration.md], [raw/svelte-flow--guide--server-side-rendering.md] |
