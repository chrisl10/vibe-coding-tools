# Implement reads and mutations

1. Preserve the selected backend. Implement a server-only DAL contract with verified identity, tenant/resource predicate and minimal DTO. Identity comes from the selected auth adapter, never submitted tenant/user fields. Check permission at the data boundary for both reads and writes. Proxy and layouts provide UX checks and cannot replace this. Sources, data security
2. Use a thin use-server action for a UI mutation, or a route.ts handler for the explicit HTTP contract. Validate all FormData/JSON/URL values using the project's existing boundary validator. The starter's small allowlist parser demonstrates mechanics and does not replace the app's schema discipline. Actions/handlers remain independently callable public-facing entry points. Sources, auth
3. Await route params using the installed version's type contract. Authenticate and authorize before database writes. Use an atomic tenant-scoped write predicate to avoid a permission-check/write race. Return a minimal typed result, distinguish malformed input, unauthenticated, denied and unexpected failures, and keep raw exception details server-side without PII. Sources, data security
4. After a successful mutation, invalidate only declared cache scopes. updateTag is Server Action only; revalidateTag(tag, 'max') permits stale content and is unsuitable when the contract requires immediate expiry. Do not equate router refresh with tag invalidation. Redirect outside a catch that would swallow framework control flow. Sources, revalidateTag, mutate
5. Exercise direct endpoint/action invocation without the UI, invalid payload, tenant B against tenant A, revoked access, duplicate submission where relevant and failure before write. Report each request/result. Handoff audit to nextjs-security plus Core Security; this implementation procedure cannot certify security.
