# Isolate cache and private data

1. Record exact installed version and whether Cache Components is enabled. Do not paste old route-segment cache flags into a Cache Components application. Follow the matching [current model](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/nextjs-stinger/references/research/raw/caching.md) or [previous model](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/nextjs-stinger/references/research/raw/previous-cache.md). The starter adds no cache directives.
2. For every read mark public, tenant, user or permission-sensitive; specify cache inputs, scope, response headers, freshness, revocation and invalidation. Default private reads to request work with verified session and no shared cache. Under the previous model explicitly inspect no-store and whole-route prerendering: an uncached fetch alone does not prove no static private output. [Sources](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/nextjs-stinger/references/research/raw/previous-cache.md), [routes](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/nextjs-stinger/references/research/raw/routes.md)
3. With Cache Components, put runtime private reads under Suspense. Normal use cache cannot call cookies/headers/searchParams, including indirectly. Arguments and captured values form cache identity but do not authorize access. Build success can miss a runtime request-API error. [Sources](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/nextjs-stinger/references/research/raw/caching.md), [use cache](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/nextjs-stinger/references/research/raw/use-cache.md)
4. Only use use cache: private after version/config support is confirmed. Current archive says it does not persist in a production server cache across requests and can keep rendered output in browser memory. It is excluded from the static shell, supports request APIs, needs cacheComponents, and still needs verified authorization. Do not claim it encrypts props, eliminates browser exposure or makes logout safe by itself. [Source](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/nextjs-stinger/references/research/raw/private-cache.md)
5. Test cold and warm public reads, tenant A then B at same URL, permission revocation, logout then back navigation, account switching, post-mutation freshness and deployment change. Inspect production HTML/RSC and HTTP/CDN behavior. Failed identity must never populate a public/shared result. Report actual content and cache headers without private values. Cache behavior NOT_RUN until an actual production-mode app exercises it.
