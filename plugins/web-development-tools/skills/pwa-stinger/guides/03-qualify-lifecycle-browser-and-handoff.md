# Qualify lifecycle, browsers and handoff

1. Feature-detect secure context and serviceWorker, register the actual approved URL/scope and report errors without private data. No automatic skipWaiting or clients.claim. Record waiting/active/controller states; arrange an accepted update prompt with Impeccable and test version transitions with multiple open clients and unsaved work.
2. Install a versioned cache only after every approved asset validates. Delete only obsolete caches under the approved application-owned prefix at activation. Never clear all origin caches. Decide rollback/version compatibility with the actual app owner.
3. With a real target, verify registration/scope/control, online-first and subsequent offline visits, generic fallback, refresh/deep link, cache contents, query/header/method/private bypass, auth denial, logout/account switch and browser storage eviction. Test each claimed device/browser's install criteria and lifecycle behavior. Record actual commands/screens/network evidence and failed cases.
4. Source format, hashes, pure Node policy fixtures and syntax checks are limited evidence. They do not run browser ServiceWorker, CacheStorage, install UX, hydration, device persistence or the app. Mark missing target/dependencies/browser evidence NOT_RUN.
5. Submit independent Core Security review first, then independent Quality; parent owns Repository Health and approved release. Report reduced security coverage where applicable. No installs, settings, provider effects, credentials, commits or pushes from this workflow without specific authorization.
