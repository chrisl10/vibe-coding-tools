# Implement public cache and private bypass

1. Use an exact same-origin GET asset allowlist; reject query variants, authorization headers, cross-origin URLs and methods other than GET. Build the list from reviewed public static assets. Fetch precache content with credentials omitted and redirects rejected, validate status/type/MIME and expected SHA-256 before storing. Do not use cache.addAll on arbitrary application routes.
2. Cache API does not enforce HTTP Cache-Control itself. The starter additionally rejects private/no-store responses and uses a versioned application cache; these are safeguards, not proof that an asset is public. Review generated content before assigning its digest. Runtime private/session/tenant/API requests bypass worker interception and cache writes. This bypass does not disable the browser HTTP cache, CDN or prior workers; qualify those layers and accepted private response headers separately.
3. Serve cached public assets only from the named cache; public navigation uses network and receives a generic static offline fallback only on network failure. Do not substitute the offline page for 401/403 or other server responses. Do not cache successful navigation responses.
4. Keep all POST/PUT/PATCH/DELETE network-only. No background queue/retry is added without the accepted idempotency key, authorization freshness, durable sync state, duplicate handling and conflict-resolution contract. A sync event is not that contract.
5. Map other persisted stores and old worker caches. Logout clears only approved owned data and UI state; disconnected revocation cannot guarantee erasure or freshness. Do not promise offline private access or account switching isolation from public-asset-only fixtures.

Grounding: Cache, offline operations, storage. Exact public allowlist and private bypass are derived security policy, not framework defaults.
