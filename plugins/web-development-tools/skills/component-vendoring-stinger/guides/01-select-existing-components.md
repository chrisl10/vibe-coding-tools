# Select existing components

Read PRODUCT.md, DESIGN.md and the surface brief before choosing a component. Load Impeccable for design direction and the actual product token owner for enforcement. This specialist compares delivery and provenance contracts; it does not invent another taste system.

1. Inspect the project's existing primitives and accepted dependencies first. Reuse when the semantic behavior, framework and token fit satisfy the task. Record the actual deficiency before researching another library.
2. Fill [the selection worksheet](../references/selection-worksheet.md). Ask one batched question for material unknowns. Compare source-copy, ordinary dependency and vendor-fork modes against the same requirements.
3. Pin the repository revision or package artifact, inspect actual source paths, LICENSE, NOTICE, file headers, imports and registry closure. A marketing license label is insufficient. Read [the digest](../references/research/distillation.md).
4. For this researched Svelte example, shadcn-svelte supplies copied editable wrappers; Bits UI remains an installed primitive dependency unless explicitly copied. Inspect actual prerequisites rather than importing the archived versions into a different target.
5. Recommend one path with why it meets the unmet requirement and the named maintenance owner. Unknown legal compatibility goes to Software Licensing and qualified counsel. Dependency Audit owns graph, vulnerability/SBOM and release artifact evidence. A maintenance owner for vendored code outside the approved component subset remains a conditional handoff gap.
6. Hand off the completed worksheet and planned proof to the parent. No install, provider call, global setup or source write follows from a selection recommendation.

Sources: introduction, registry schema, actual MIT LICENSE, mixed NOTICE.
