# Component selection and copy worksheet

Record product/surface, framework and exact version, PRODUCT.md / DESIGN.md / surface brief, actual token owner, user task, semantic and interaction needs, SSR/hydration contract, browser/device targets, accessibility checks, theming, existing primitives and why they fit or fail. Unknown material fields block a recommendation that depends on them.

| Candidate / mode | Existing fit | Prerequisites | Styling/control | Interaction proof | Exact rights evidence | Maintenance owner/cost | Decision |
|---|---|---|---|---|---|---|---|
| Existing project primitive | Unknown | Unknown | Unknown | NOT_RUN | Unknown | Unknown | Inspect first |
| Pinned source-copy subset | Unknown | Unknown | Unknown | NOT_RUN | Actual files, licenses, notices needed | Named owner needed | Pending |
| External dependency | Unknown | Actual target graph needed | Wrapper/override contract | NOT_RUN | Package distribution evidence needed | Dependency Audit + owner | Pending |

Recommend one path with the decisive reason. Never infer that copied wrappers are the whole library, that an npm dependency was vendored, or that a root MIT label covers bundled code. Approved paths and change authorization must be explicit before writes. Preserve previous source snapshot, file mapping and local changes; no overwrite flags.

Proof ledger: typecheck/build, target interaction tests, keyboard/focus, screen-reader manual checks, contrast, touch targets, light/dark/high-contrast, reduced motion, responsive overflow, SSR/hydration, exact license review, browser/native host execution. Each entry has PASS/FAIL/NOT_RUN/UNKNOWN, command or method, target/version, date, artifact path and limitation. Documentation alone is never PASS.
