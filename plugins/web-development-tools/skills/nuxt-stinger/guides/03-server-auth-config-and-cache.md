# Server routes, auth, config and cache

1. Use server/api for /api-prefixed handlers and method suffixes for method-specific endpoints. Validate path/query/body at the boundary using the project's existing validation tool. Vue page middleware cannot protect a direct API request.
2. Call the accepted server session adapter on every sensitive entry. Check resource permission and tenant membership server-side before querying or serializing; a client tenant key is untrusted. Session existence alone is insufficient. Mutations need the accepted CSRF/origin/replay policy and method contract. Do not adopt nuxt-auth-utils merely because the official recipe uses it.
3. Return the minimum approved DTO. Keep secret runtimeConfig keys server-side, keep public config deliberately publishable, and inspect HTML, payload JSON and client assets for leaks. Resolve environment names only; do not read/write values.
4. Inventory routeRules, cached wrappers/functions, prerender output, payload extraction, CDN/reverse proxy and browser caches. Default private pages and APIs to cache:false plus Cache-Control private,no-store, without broad swr/isr/prerender. Match both exact paths and descendants. Headers alone do not disable a cached function or override upstream policy.
5. Only approve public cache scopes after showing that every variant is public. If private caching is explicitly required, obtain a reviewed partition/invalidation contract and actual two-principal/tenant/logout tests. varies or a tenant key cannot serve as blanket cache safety evidence. Check Nitro major before choosing its cached-handler API.
