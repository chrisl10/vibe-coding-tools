# Qualify the recommendation and hand it off

1. Complete the decision template with one recommendation, route delivery model, backend boundary, owner graph, acceptance ledger and unresolved constraints.
2. Map required evidence to the selected framework: direct/deep-link navigation, initial public HTML where needed, form success/error/refresh, auth/tenant denial, state and actual deployment mode. Do not infer these behaviors from another framework's tests.
3. Resolve actual implementation owners. Explicitly mark missing Next.js/Vue/Nuxt owners when unavailable. Recommending Nuxt can be technically supported while implementation remains blocked pending an authorized owner.
4. Reuse selected Infrastructure Fit/Launch Assets for hosting/readiness, and Core contracts/Library for accepted build handoff. No setup/implementation happens solely because selection finished.
5. Deliver the advisory result and evidence limits. A vertical slice is future implementation work with separately authorized scope; do not report verified framework behavior from this worksheet or encoded fixture checks.
