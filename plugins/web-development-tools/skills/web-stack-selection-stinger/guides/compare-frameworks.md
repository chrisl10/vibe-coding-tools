# Compare framework tracks

1. Compare the same product inputs across React19/Vite, SvelteKit, React/Next.js and Vue/Nuxt. Use capabilities and constraints, not rankings, popularity or unsupported performance claims.
2. Distinguish UI library from app framework and build tool. For React/Vite, name routing/data/mutation/backend decisions still needed. For SvelteKit/Next/Nuxt, qualify actual rendering/server/adapter behavior rather than assuming the framework does every feature safely.
3. Match stable/public/dynamic/signed-in routes to a delivery model. Verify chosen version and host deployment support. A static-export restriction can rule out a server-only feature unless the accepted separate backend supplies it.
4. Account for actual team skills and existing code. Native reuse needs qualified target/runtime evidence; do not promise DOM/UI reuse by language similarity.
5. Return one recommendation with source-backed fit, meaningful competing discriminator and facts that would change it. Missing implementation owner is a delivery gap, not a reason to falsify technical fit.
