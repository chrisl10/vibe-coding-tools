# Web stack intake

Product/milestone: [quick website, SPA, SSR app, existing product]
Reader/team context: [experience, existing codebase, maintenance owner]

| Decision | Supplied constraint | Evidence or assumption | Missing question |
|---|---|---|---|
| Content/search | public routes, discoverability, content freshness | exact user goal | unknown |
| Interaction | forms, dashboards, browser APIs, offline/state | feature requirements | unknown |
| Rendering | static, request HTML, browser app, mixed routes | need rather than buzzword | unknown |
| Backend/data | existing API/language, auth, tenancy, payments, workers | accepted contract | unknown |
| Native reuse | native/wrapper targets, shared logic, actual UI needs | explicit scope | unknown |
| Team | React/Svelte/Vue skills, current repo, learning capacity | owner report | unknown |
| Hosting | runtime/adapter, server availability, regions and budgets | accepted host constraints | unknown |
| Design/components | product tokens, library/vendoring/license needs | actual selected owners | unknown |
| Acceptance | behavior/content/accessibility/security evidence | planned test owner | unknown |

Ask only missing facts that change selection. Existing framework experience is an input, not proof that every neighboring server framework is qualified.
