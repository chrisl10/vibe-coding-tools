# 15: Build an independent Payload CMS

Use for O070, including when there is no public application yet. This procedure supersedes copied Phase7/9 examples for CMS access, public contract and runtime boundaries. Read [distillation](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/website-stinger/references/research/scoped-website/distilled.md) and fill [CMS contract](../templates/payload-content-contract.md) before schema code.

1. Inspect installed Payload, Next.js, adapter and Node versions plus existing collections and migration ownership. Ask for content types, fields, editorial roles, publication/preview flow, locales, media lifecycle and actual consuming clients. Do not carry ClearDeck, testimonials, app_settings, SaaS account roles or a product's business tables into an unrelated CMS. Collections model repeated records; Globals model singular settings. Missing field decisions remain named gaps. [Payload scope](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/website-stinger/references/research/scoped-website/raw/payload-overview.html).
2. Keep the CMS application and runtime separate from a Svelte public client. Next.js hosts this playbook's Payload admin. CMS owns DB migrations, auth and privileged code; public site consumes a reviewed REST contract. Supabase is one permitted Postgres host, not an obligatory business-data project. Record actual DB adapter, schema ownership, migration plan and allowed permissions. No invented `CREATESCHEMA` privilege or superuser requirement. Experimental schemaName needs installed-version verification. [Postgres](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/website-stinger/references/research/scoped-website/raw/payload-postgres.html).
3. Define every collection/global CRUD access rule, field-level read/write and role changes. Anonymous content reads return a published-only query constraint on `_status`; trusted editor access is based on the actual allowed CMS role. Restrict Users collection create/read/update/delete and role creation/update to the accepted policy. Default authentication is not a role policy. Do not expose email/author accounts through relationship expansion. [Access](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/website-stinger/references/research/scoped-website/raw/payload-access.html), [drafts](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/website-stinger/references/research/scoped-website/raw/payload-drafts.html).
4. Declare public field selection, slug uniqueness/encoding, relationship depth, pagination, missing-content behavior and schema evolution. Query filters help select content but cannot prevent a direct draft request. Server-side calls use an absolute trusted CMS base URL; browser-origin CORS applies to browser fetches, not server-to-server authorization. CORS/CSRF settings never replace access control. Explicit Local API operations pass `overrideAccess: false` and user/request context when caller-scoped; privileged maintenance operations require separately authorized scope. [REST](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/website-stinger/references/research/scoped-website/raw/payload-rest.html), [Local access](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/website-stinger/references/research/scoped-website/raw/payload-local-access.html).
5. Store secrets only in CMS/server environment. Fail startup on missing secret instead of a hardcoded fallback. Generated Payload types express shapes, not a runtime trust boundary. Return only reviewed public data from server loads; never serialize tokens or CMS privileged config. Svelte private imports belong in server-only files. [Server modules](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/website-stinger/references/research/scoped-website/raw/svelte-server-only.html).
6. Decide SSR versus prerender with accepted publishing latency. SSR needs actual cache freshness; static publishing needs authorized rebuild mechanism. Draft preview is authenticated, no-store, and isolated from public cache. A `preview=true` query flag is not authorization. Verify cache eviction after publish/unpublish; inspect paginated entries so posts beyond page1 are included. Use actual supported Lexical serializer/version and review HTML sanitization for any HTML sink; a named hypothetical serializer or React renderer does not establish Svelte compatibility. [Page options](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/website-stinger/references/research/scoped-website/raw/svelte-page-options.html).
7. Choose durable media storage and upload policy separately from DB. Validate type/size, private-media authorization and deletion policy. Local development files do not prove persistence on hosting. Credentials, storage provisioning and provider writes remain owner actions. [Storage](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/website-stinger/references/research/scoped-website/raw/payload-upload.html).
8. In an authorized local disposable CMS fixture, test anonymous published read, direct draft ID/filter read denied, anonymous write denied, editor allowed operations, cross-role denial, role escalation denied, relationship private-field denial, pagination, missing content, media persistence and publish/unpublish freshness. Record exact request/status/body shape with secrets removed. Before this is executed, mark all runtime rows pending. Run actual project build/type checks, Security then Quality then repository gate.

Deliver CMS schema/API contract, local implementation and observed readiness report. This source update supplies procedure and worked fixtures; it does not claim an app ran, a provider exists, or production is ready.
