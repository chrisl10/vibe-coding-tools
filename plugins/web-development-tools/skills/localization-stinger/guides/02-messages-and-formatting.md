# Implement messages and explicit formatting
Grounding: ICU messages, Unicode plurals, MDN plural rules, MDN numbers, MDN dates.

1. Use the selected installed engine's version and syntax. Compile ICU resources through that engine; reject malformed patterns, missing arguments and placeholder type mismatches. Preserve whole sentences and translator context. Do not split prose into fragments or implement a homegrown ICU parser.
2. Verify plural/select branches using locale rules and actual message engine output. Include zero, one, two, many, fraction and any explicit exact-number overrides, with required fallback coverage. Cardinal and ordinal cases are distinct. Intl.PluralRules only supplies categories; the bounded example deliberately does not parse ICU.
3. Keep money amount/currency as authoritative domain inputs. Pass approved currency explicitly to Intl.NumberFormat. Formatting is not an exchange rate, payment calculation or country-to-currency assumption. Do not round stored balances through localized display strings or parse formatted numbers as machine data. Route money-flow changes to Payments and Core security.
4. Specify locale, timezone, calendar and hour-cycle when the target contract requires them. Distinguish an instant from a date-only value and a scheduled local wall time; do not turn a birthday into a shifting timestamp. The example accepts a machine instant and requires an approved timezone; it does not resolve ambiguous DST scheduling or choose a user timezone.
5. Keep semantic values separate from display parts. Use formatToParts for necessary structured UI without punctuation/string surgery. Record resolvedOptions and runtime/ICU version. Test runtime support and server/client output boundaries; do not assert identical output for every engine/data version.
6. Validate the actual engine and target tests. Report synthetic Intl mechanics separately from ICU compilation, live currency operations and browser evidence.
