# Localization evidence digest
Captured 2026-10-08 UTC. Current official pages are freshly fetched; publication dates vary and older guidance is not represented as newly published. Raw bodies and fetch metadata are in [the manifest](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/localization-stinger/references/research/raw/manifest.json). The following claims are paraphrases; constructed examples and project policies are explicitly distinguished.

| Claim | Archived primary source | Application boundary |
|---|---|---|
| Document language belongs on the HTML element; tags follow BCP 47. | [W3C language](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/localization-stinger/references/research/raw/w3c-language.html) | The supported locale list and fallback order are product decisions. |
| Overall RTL direction is declared with HTML dir; CSS alone does not carry that semantic. Inline dynamic text can use isolation and automatic direction. | [W3C direction](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/localization-stinger/references/research/raw/w3c-direction.html) | An Arabic fixture is not linguistic or layout conformance proof. |
| Logical CSS describes inline/block edges relative to writing mode. | [MDN logical properties](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/localization-stinger/references/research/raw/mdn-logical.html) | Review intended mirroring of individual controls rather than reversing all elements. |
| ICU MessageFormat supports plural and fixed-keyword select submessages; keeping alternatives together provides translators context. | [ICU messages](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/localization-stinger/references/research/raw/icu-messages.html) | Use the project's installed message engine; Intl.PluralRules is not an ICU message parser. |
| CLDR plural selection has operands and locale-specific categories; fractions affect selection. | [Unicode number rules](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/localization-stinger/references/research/raw/unicode-plurals.html) | Validate zero, integers and fractional cases for each supported resource contract. |
| Intl APIs accept locale preferences and formatting options. | [MDN Intl guide](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/localization-stinger/references/research/raw/mdn-intl.html) | Supported locale negotiation is independent of account identity. |
| DateTimeFormat formats dates; an omitted locale/timezone can depend on runtime defaults. | [MDN DateTimeFormat](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/localization-stinger/references/research/raw/mdn-datetime.html) | Require an approved timezone for cross-runtime output and record calendar/hour-cycle policy. |
| NumberFormat formats currency using explicit currency options and has formatToParts. | [MDN NumberFormat](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/localization-stinger/references/research/raw/mdn-number.html) | Formatting preserves the amount; foreign-exchange conversion is outside this skill. |
| PluralRules selects categories for locale-sensitive plural behavior. | [MDN PluralRules](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/web-development-tools/skills/localization-stinger/references/research/raw/mdn-plural.html) | Different runtimes may ship different ICU/CLDR data; record runtime evidence. |

Small source samples: W3C direction says “Never use CSS to apply the base direction.” ICU message guidance says “Use a "plural" argument to select sub-messages”. Samples total fewer than 25 words from each source.

Derived project policy: explicit approved locales, supported-list allowlisting, stable server/client context, text-only resource rendering, placeholder contracts, privacy boundaries, and named translation reviewer signoff are workflow requirements. These are not quoted standard requirements. Synthetic mechanics validate only their stated contract and do not claim WCAG compliance, complete RTL quality, security clearance or native support.
