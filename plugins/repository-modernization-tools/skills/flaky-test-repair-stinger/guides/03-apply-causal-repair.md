# Apply a causal repair without weakening coverage

DERIVED procedure, the digest. Implementation starts only with sufficient observed cause evidence or an explicit owner-approved experiment.

1. Freeze a repair scope tied to the observation: exact test/fixture files, cause, expected behavior and permitted effect. Record the original assertion, input/oracle, error cases, coverage and accepted timeout/tolerance. Preserve accepted product interfaces and current other-agent ownership.
2. Prefer the smallest repair that removes the evidenced condition: per-test owned state, reliable setup/teardown, completion join, restored scoped mock, deterministic clock/seed seam, stable semantic locator or readiness wait for the same accepted condition. Changing a genuine product race/service fault belongs to its language/framework owner; hand it the exact failure/contract rather than hiding it in test retries.
3. A supported locator assertion that awaits the same semantic result can fix a premature snapshot assertion. Preserve the expected value and accepted deadline; do not inflate timeout beyond the requirement or force clicks that bypass actionability. Explain the causal readiness evidence. Assertions, actionability.
4. Preserve the behavioral oracle. Do not delete/skip/quarantine/xfail tests, auto-approve snapshots, turn strict equals into broad contains, swallow exceptions, drop negative cases or add retries just to pass. An assertion/tolerance/SLA change that alters requirements needs a separately accepted owner decision and explicit coverage justification; this repair does not approve it.
5. Use supported scoped fixture controls and clean only resources the test created. Avoid process-global environment mutation under parallel tests. Keep teardown working after setup failure and ensure asynchronous work actually completes before resource reuse. Go testing, pytest fixtures.
6. Inspect the diff for assertion count/meaning, collection count, fixture scope, retries/skips/timeouts and mocked-versus-real execution. Add or preserve a targeted regression that exercises the identified cause and proves the original failure would be detected. A duplicate test mirroring implementation adds no proof.
7. Have the browser/language implementation owner review framework mechanics if relevant; keep CI topology, dependency installs and production effects out of this repair. Record why the exact change should remove the cause, what remains uncertain and how to revert the owned diff without deleting evidence.
