# Prove the narrow repair on the final candidate

DERIVED procedure. Independent Core Quality remains the final implementation audit after Security; source-authored checks here do not replace it.

1. Pin the final relevant candidate/test/fixture/config/lock hashes before execution and compare after. Use the original observed failure condition and accepted assertion oracle. An intervening relevant change makes old proof STALE; do not relabel old results or rerun unrelated passing checks.
2. Use the approved bounded trial matrix: targeted regression, original order/seed/parallel condition, relevant neighboring fixture tests, and actual browser/integration/native target where the repaired claim needs it. Run only existing authorized tools, within budget. Cached Go passes, zero collected tests, skipped cases or a green retry do not count as executed repair proof. [Go cache](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/repository-modernization-tools/skills/flaky-test-repair-stinger/references/research/raw/go-test-command-source.md), [retry labels](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/repository-modernization-tools/skills/flaky-test-repair-stinger/references/research/raw/playwright-retries-source.md).
3. Record each invocation/attempt/trial with start/end, exit/signal, candidate/env/seed/order/worker identity, assertion/collection counts and sanitized output hash. Preserve all failures and error signatures; never report only the last successful run. Distinguish fixture-only/browser/real integration/native/CI evidence. No supplied consumer means all behavioral rows NOT_RUN.
4. Compare the pre/post assertion and coverage inventory. Demonstrate the original failing condition is still meaningfully checked, setup/teardown behaves on error and unaffected relevant cases remain covered. If a safe authorized baseline experiment shows the old test failing and the repair passing under the same controlled cause, record both; otherwise report that causal proof gap instead of inventing it.
5. Report exact observed trial counts and residual uncertainty. Finite passes do not prove absence of flakiness, independent trials or statistical confidence. A final candidate unresolved under original conditions remains OPEN/INCONCLUSIVE; source code plausibility alone is not a repair verdict.
6. Complete [the evidence worksheet](../templates/failure-repair-evidence.md) and consumer library report. Run independent Security, resolve medium-or-higher findings and affected checks, then Quality against the same candidate. Parent loads repository health and preserves user review/commit-push approval. CI reruns/publication require separate specific authority; queued jobs never count as results.
