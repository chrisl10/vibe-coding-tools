# Capture the observed failure

DERIVED procedure, source digest. Use [the worksheet](../templates/failure-repair-evidence.md). This specialist repairs from observed failures; no consumer failure supplied means source guidance only.

1. Record the exact reported test/parameter, task/plan and expected behavior. Preserve the raw failing assertion and stack/trace with coordinates, attempt number, timestamp and status. Redact secrets/customer payloads before shared evidence. Hash permitted raw artifacts and record any redaction boundary; do not invent missing logs or historical repro counts.
2. Pin full source/base/candidate revisions plus dirty relevant files, test/fixture/configuration/lock hashes, runner/runtime/browser/OS versions, command/cwd, worker/shard/order/seed, timezone/locale/clock, resource limits and allowed external service identities. Capture relevant environment names/nonsecret values only. A secret or production data dump is not environment capture.
3. Distinguish assertion failure, setup/teardown error, product exception, infrastructure outage, timeout, missing dependency and cancelled/incomplete execution. A single failure supports a hypothesis, not a confirmed flaky-test diagnosis. Preserve first-attempt failures even when a later retry passes. Runner labels.
4. Inspect the failing test and immediate fixture/product dependency boundaries only. Inventory shared files/database records/ports/process environment, global mocks/listeners, job teardown, clocks/randomness and network calls. Identify the actual language/browser/CI owners before edits. Do not change an unrelated suite to gather context.
5. Use existing permitted tooling. Collect the failing attempt’s diagnostics where available; a first-retry trace may come from a replacement worker, so label it correctly. Traces may contain private DOM/network data; capture minimal authorized diagnostics, not broader user material. Trace.
6. Set explicit total time/attempt/resource budget, reset procedure and stop criteria before repro. Default at most two identical failed invocations, and stop after three failed approaches. A larger repeated-trial plan requires an explicit task budget/override; otherwise do not increase repetitions or runner retries to hunt for green. Missing runner/consumer permissions blocks execution, not permission to install.
