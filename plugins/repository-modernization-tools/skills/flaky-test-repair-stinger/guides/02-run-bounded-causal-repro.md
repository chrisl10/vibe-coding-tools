# Run a bounded discriminating reproduction

DERIVED procedure. Preserve [failure identity](01-capture-observed-failure.md); use [the hypothesis record](../references/REFERENCE.md). No live CI or provider call follows from a reproduction plan.

1. State one causal hypothesis tied to the exact observed failure, and one variable whose change should alter that signature. Hold candidate/assertion/data constant where possible. Label reproduction as observed failure, inconclusive/no reproduction, or evidence for/against the hypothesis. Never claim a serial pass alone proves a race.
2. Reproduce the original condition with existing authorized runner/tooling and bounded fixture data. Disable runner retries for diagnostic attempt accounting where the project permits a command override; record every initial/retried/skipped/cancelled result separately. Do not change repository retry settings or quarantine the test.
3. For order/isolation, record actual predecessors, seed/order, worker count and shared resource names. Compare a targeted run against the observed order/parallel condition without changing genuine assertions. Browser contexts do not isolate a shared database/server; namespace fixtures and identify cleanup ownership. Go shuffle records a seed; Go -count=1 avoids cached passes. Use supported built-ins only, no new random-order plugin. Isolation, Go.
4. For state leakage, inspect setup/teardown and async/thread/goroutine/process joins. Reset only exact operation-owned fixtures, never broad user data. A yield fixture failing before yield needs a setup-failure cleanup design. Test cleanup failure as a different condition rather than assuming a finally block covers it. Fixtures.
5. For time/randomness, capture timezone/locale, seed, timer ownership, wall versus monotonic clock and expected deadline. Inject deterministic clock/randomness only at an accepted owned seam; install before relevant calls and restore scope. Keep genuine timing/deadline behavior tests separate. A long sleep, larger timeout or dropped ordering assertion does not establish a cause. Clock.
6. For network, distinguish service/product failure from test-controlled nondeterminism. A scoped mock/fake can isolate a boundary but must retain contract/error behavior and disclose it. Do not silently replace required integration proof with a successful mock or replay a paid/external request. Network, monkeypatch.
7. Before each adaptive follow-up, state what changed and why that should change the outcome. Keep trials within the approved budget. If unchanged failure repeats twice, three approaches fail or evidence cannot distinguish causes, stop with the exact ledger and recommended owner action. No endless rerun, blanket serial mode or unrelated infrastructure changes.
