## Dynamic usage and vendor qualification

For every proposed unused dependency, read the actual computed/string imports, reflection/name registries, generated or framework-discovered entries, scripts/CI, optional/platform branches and public/downstream consumers. A search with no static imports or a scanner graph gap does not prove it unused. Preserve unresolved packages and record exact file/line or runtime evidence; do not hide findings with ignore patterns to pass removal.

For a vendored or patched package, pin upstream identity/revision, byte hashes, license/notices, local patch list and accepted ABI/public contracts before removal or replacement proposals. Preserve patches and attribution. Removing a direct declaration does not establish that transitive instances, deployed code, vulnerabilities or costs disappeared. Require measured graph/artifact evidence for those separate claims. Current specific authorization must name any later destructive paths or replacement; a proposal is not approval.
