# Constructed remediation cases

Execution status: NOT_RUN. These cases define expected source workflow behavior; they are not customer application tests or proof of live routing.

| Case | Expected outcome |
| --- | --- |
| Knip flags a route loaded by a runtime-computed path | Inspect actual dispatch/configuration and retain as Live or Unknown until qualified; no deletion |
| A reflection-based serializer references a class by name | Read registry, discovery and generated consumers; static imports alone cannot classify it dead |
| A package export points at generated output absent from the scan | Record missing graph coverage and block dead-code conclusion |
| Two copies have similar syntax but distinct tenant and refund policies | Keep policies separate unless the same-concept extraction preserves each accepted behavior |
| Shared abstraction requires six booleans to preserve existing differences | Reconsider the abstraction and record the independent responsibilities |
| Giant service has one transaction across several operations | Preserve transaction and process semantics in proposed seams; no automatic microservice split |
| Refactor changes error status, timeout, auth order or side-effect count | Stop equivalence claim and require a separate accepted behavior change |
| Strangler proposal has no state reconciliation or recovery condition | Keep cutover unapproved and unexecuted; document missing proof |
| Debt score guesses incident frequency or customer revenue impact | Mark unknown; rank only from known evidence and labelled assumptions |
| Vendor update overwrites a local security patch | Reject proposed wholesale sync; preserve patch and compare upstream resolution first |
| Upstream license file is absent in proposed vendoring diff | Block readiness and preserve notices; seek license interpretation where needed |
| Candidate tests pass but run on a different revision than the diff | Withhold qualification until exact candidate evidence exists |
