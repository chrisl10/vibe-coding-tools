## Proposed policy, supported by those limits

O122: treat scanner output as a candidate list. Read dynamic consumers, framework discovery, reflection/name dispatch, package exports, generated code and conditional jobs before each deletion proposal. A search with no hits is insufficient when names are constructed. Missing evidence means unknown, not dead.

O124: compare duplicated regions by responsibility, change history and behavior. Extract only when they represent the same evolving concept. Similar syntax alone is insufficient. Preserve independent differences instead of adding flags to force a common abstraction. This is a design review policy, not a statistical claim about clone detectors.

O126: first propose a boundary within the current process with explicit input/output, dependency and transaction ownership. A microservice introduces a separate deployment and operational decision, requiring its own accepted scope. File length alone does not prove an appropriate service boundary.

O128: propose one observable capability at a time, identifying routing, state ownership, failure behavior and rollback conditions. Any traffic switch, provider change or destructive retirement requires current specific authorization. A strangler worksheet is preparation only.

O133: prioritize debt against known customer impact, incident evidence, change frequency, security exposure, cost and reversibility. Unknown quantities remain unknown. A named assumption or illustrative score is not measured business impact.

O134: record upstream identity/revision, imported bytes, license and notices, local patch list, compatibility evidence and future update ownership. Keep patches and notices through any proposed upstream comparison. Provenance or a version pin alone does not prove safety or license compatibility; route legal interpretation to counsel.

## Evidence boundaries

The six workflow policies require actual repository observation and existing relevant checks. Constructed cases are NOT_RUN. No scanner install, real repository deletion, migration, refactor, branch operation or vendor update was executed for this source proposal. Domain specialist owners retain implementation responsibility.
