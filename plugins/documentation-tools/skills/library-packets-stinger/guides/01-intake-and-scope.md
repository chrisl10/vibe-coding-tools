# Intake and scope

1. Load the [invocation questions](../references/intake.md). Use answers already supplied. Confirm the library root, subject, readers, product account, public boundary and output location before dependent work.
2. Explain the supported output contract once: each chosen document has Markdown, editable Word, PDF and a citation list, with a real Legion footer. Do not ask the user to reconfirm those defaults.
3. Detect whether the harness can read local folders, create files, render DOCX/PDF and display page images. For plain ChatGPT without a local executor, request the library as an accessible attachment/archive or connector reference. A typed slash phrase is not evidence that a native command or folder permission exists.
4. Record the source roots, output folder, user decisions, deadline/budget and unavailable capabilities in the private intake record. Do not place private paths or setup commentary in public reader documents.
5. Select candidate documents from the [catalogue](../references/document-catalogue.md), then let the coverage pass decide which can be produced. Do not promise a document count before reading the sources.
