# Turn a PRD into a plain-language reader packet

Explain the selected PRD so a new coder can describe the intended behavior, limits and unresolved decisions without mistaking the plan for a shipped feature.

1. Use existing Library Packets intake, evidence inventory and publication boundaries. Confirm reader/decision, exact PRD revision, audience eligibility, accepted contracts, observed implementation evidence and requested formats. This guide changes no source PRD, accepted contract or Library lifecycle.
2. Extract each material requirement into the preservation ledger before simplifying it: actor, action, object, authorization, conditions, sequence, result, Draft/Accepted status, current/target state, exception and unresolved decision. Keep the exact source quote and locator. Mark unsupported implementation evidence Unknown.
3. Separate three accounts: what the current source shows, what an Accepted requirement calls for, and what a Draft proposes. An Accepted requirement is not proof of deployment. Preserve restrictive wording, such as only owners, after approval, within that workspace and never automatically, in the reader account.
4. Resolve selected Technical Explainer for its existing bounded analogy, glossary and fidelity method when the packet needs a novice explanation. Supply the source ledger and audience constraints. Library Packets keeps manuscript/citations/Word/PDF production and page review ownership; Explainer does not change requirements or authorize public disclosure.
5. Draft the reader manuscript with a concrete outcome first, then a plain account of permitted and denied cases, ordered behavior and limits. Explain why a relevant technical term appears; keep exact identifiers in internal engineering evidence when the public audience cannot receive them. An analogy illustrates the same constraints and grants no new product behavior.
6. Apply the existing semantic claim review to the rendered paragraphs and diagrams, not just quote presence. Verify that the reader can recover every material ledger field. If simplification drops an actor restriction, exception or status, revise the passage before format rendering. Use the existing packet build/review pipeline for requested formats; a Markdown draft cannot stand in for inspected Word/PDF.
7. Include one teach-back question, with reader response and understanding pending until a human answers. Retain unanswered requirements questions in the private gap record. Record readability estimates only if computed with a stated method; never treat a grade estimate as proof of comprehension.

Grounding: [update digest](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/documentation-tools/skills/library-packets-stinger/references/research/novice-explanation/digest.md). Its dated capture and exact-source ledgers preserve this workflow's provenance.
