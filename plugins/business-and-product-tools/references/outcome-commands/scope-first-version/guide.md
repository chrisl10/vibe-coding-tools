# Workflow guide

1. Load the installed `pest-controller-suit` Core skill and consult its roster before making any routing decision. This is the first instruction, always, no exceptions. Source work resolves component ownership from root `plugin-catalog.json`; installed work uses Core's explicit selected-plugin registry and resolver. Missing Core blocks routing. Load each selected pair's Stinger and required guides before work, and verify actual host tools/delegation. Cached files do not prove selection. Dispatch registered Drones at top level only when delegation is authorized; otherwise execute the selected paired procedure directly and report that fallback truthfully. No invented roles or nested dispatch.

2. Confirm the target user, one job, measurable outcome, validated assumption evidence, budget/time constraint, and existing product context. Reuse supplied decisions; ask only for material gaps. If no assumption test exists, discovery-research-wasp-drone designs the smallest invalidating test and marks the build recommendation provisional. Do not fabricate interviews or validation.
3. Have discovery-research-wasp-drone separate the user opportunity from the proposed solution. Rank candidate scope against the same outcome and choose one smallest useful end-to-end path. List excluded features with the consequence of deferral, not a second roadmap disguised as the first version.
4. Once the winning opportunity and solution are validated, have library-wasp-drone author the first-version PRD from that discovery packet. If validation is missing, deliver the discovery/test packet and provisional scope only; do not author a build PRD or finalize implementation handoff. It must contain actor, trigger, observable success, failure states, data needs, privacy/security boundaries, accessible UX, operational ownership, and explicit acceptance tests. Discovery owns research, Library owns requirements; one does not substitute for the other.
5. Have contract-writing-wasp-drone inventory shared API/event/data/permission/state boundaries. Leave missing agreements Draft until the user accepts the exact CTR revision. Library pins the accepted revision in provider and consumer PRDs before parallel dependent work. Existing accepted terms remain accepted; do not re-ask merely because this command was invoked.
6. Have estimation-wasp-drone forecast only the bounded scope using observed history where available and conditional ranges otherwise. Record learning, review, rework, external dependencies and calibration milestone. Do not promise a completion date or apply a universal AI multiplier.
7. Deliver the selected scope, PRD path, validation evidence, exclusions, acceptance ledger, contract pins, estimate assumptions and first unresolved dependency. This command prepares requirements; it does not scaffold or implement the application.

## Inputs and host qualification

Use trailing invocation text exposed by the actual host; `$ARGUMENTS` is supported only where documented. Reuse answered inputs and accepted decisions. Ask one concrete batch for unresolved material inputs before dependent work, while continuing independent authorized work. Claude/Cowork uses the owner flat command, Cursor its generated command projection, and Codex the owner's generated `source-command-scope-first-version` skill. Source generation is not installation, role discovery, or runtime proof. Resolve all resources against the selected carrier root. A missing required owner blocks its dependent boundary and is named in the report; optional branches require only their own selected dependencies.

## Output contract

Report status, selected owner/version and paired procedure, concrete artifacts, accepted contract pins, actual checks and their results, evidence limits, unfinished boundaries and the smallest unresolved user decision. Keep source/static checks, mock/browser behavior, native execution, packaged artifacts and provider evidence separate. Permission to create a source workflow does not authorize installation, provider writes, credentials, spend, commits, push or publication.
