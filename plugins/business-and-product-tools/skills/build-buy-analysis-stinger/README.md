# Build, buy or partner analysis

Compare three sourcing approaches for one accepted functional slice. Produce a local advisory decision with requirements, dated evidence, partial lifecycle costs, responsibility and exit constraints. A missing required behavior blocks a supported winner.

Read [scope](guides/01-bound-the-decision.md), [comparison](guides/02-compare-lifecycle-and-exit.md) and [decision](guides/03-recommend-and-handoff.md) in order. Use the [worksheet](references/templates/decision-worksheet.md), [fictional completed case](examples/completed-decision.md) and [negative cases](examples/negative-cases.md). The [distillation](references/research/distillation.md) links five dated primary captures and hash manifest.

Runtime is advisory analysis. No sourcing contract, account, trial, purchase, implementation, credential entry or API export is performed. Parent registration/distribution and independent construction gates are separate. Domain sources are current acquisition snapshots; publication recency is explicitly limited. Harness formats derive from Queen's existing research and templates.

Discovery, Competitive Research, Capacity Planning, Services Quoting, economics, Legal/License, Security and runtime specialists retain their separate authority. Resolve related selected owners through trusted Core before optional dispatch.
