# Negative cases: source review scenarios

All cases are constructed and NOT_RUN. They specify expected analysis behavior, not customer or native runtime tests.

| Input trap | Required behavior |
|---|---|
| Buyer asks for best vendor with no user job | Ask one scoped requirements batch; no vendor winner. |
| Cheapest option fails mandatory export requirement | Keep FAIL visible; cost score cannot override it. |
| Blank operating/exit costs | Retain UNKNOWN; label partial total, not zero. |
| API exists, salesperson says unlimited | Capture method/app/plan limits and terms; classify sales claim separately. |
| Export ZIP has file URLs | Do not call file bytes preserved or migration proven. |
| Partner invoice paid, no IP clause | Hand rights applicability to Legal/License; do not invent ownership. |
| Public vendor security badge | Security assurance stays pending actual scope/evidence review. |
| Existing tools are installed in an unrelated cache | Resolve selected-owner availability; missing owner blocks dependent conclusion. |
| Trial suggested by official guidance | Prepare specification only; no account/spend/credentials implied. |
| Real data asked to bulk export through API despite restriction | Preserve applicable terms uncertainty; no circumvention or automatic export. |
| Assumed AI coding makes bespoke ten times faster | Reject invented acceleration; request Capacity/Estimation inputs. |
| Partner sells managed service and bespoke code together | Separate delivery/IP/operating responsibilities and costs, avoid duplicate accounting. |
| All options have unmet mandatory unknowns | Recommend one evidence task; no unsupported winner. |
| Need not validated | Discovery owns demand evidence; sourcing comparison cannot bless construction. |
