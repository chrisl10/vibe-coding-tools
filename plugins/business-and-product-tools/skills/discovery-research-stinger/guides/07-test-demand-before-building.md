# Test demand before building

Grounding: distillation, especially SBA/NSF direct research, Strategyzer experiment criteria, and the existing assumption guide.

1. Read the desired outcome and assumption map. Confirm one customer segment, concrete current problem, competing workaround, proposed offer, and the next decision the test changes. Do not generate interview evidence from public market descriptions.
2. Select one high-risk desirability or viability assumption. Split "they need it and they will pay" into separate claims. Record what observation would contradict each. Read the existing experiment-design guide to choose an appropriate prototype or direct-research method.
3. Fill [the test record](../templates/demand-test-record.json) before exposure: assumption, target population, recruitment/channel, inclusion/exclusion, stimulus, actual exposure definition, metric numerator/denominator/unit/time window, proxy limitation, threshold and minimum observation conditions, failure/stop rule, owner, budget, and planned start/end. These values are project decisions, not universal conversion benchmarks. Record the declaration timestamp and criterion version.
4. Record participant sourcing, permission/consent procedure, pseudonymous participant codes, channel, source provenance, incentives, and expected sample/coverage limits. Retain only necessary records in the approved project location. The template never grants contact, recruitment, recording, payment, ad spend, landing-page publication, or customer-data access. Ask for specific action authorization before running an external test.
5. Check economic/logistical feasibility: contribution/cost assumptions, delivery hours, operational dependencies, access, support burden, budget, available audience/channel, and deadline. Delegate formal pricing/unit-economics or legal/analytics questions to the selected existing owner. A positive demand proxy does not erase a cost or delivery constraint.
6. Design the smallest observation that could disconfirm the assumption, including negative cases: ignored offer, existing workaround preferred, wrong participant, interrupted test, repeat exposure, incentive bias, and no feasible recruitment. A click is initial interest; a signup does not prove use or payment. Record exactly what the chosen proxy can establish.
7. Mark the test planned/unexecuted until actual authorized observations exist. For an executed test, record source paths, times, exact counts, contradictory observations, exclusions with reasons, and failures. Do not invent interviews, quotes, participants, or conversion counts. Do not omit nonresponses from a denominator that was declared to include them.
8. Preserve the original criterion. If a measure, population, sample condition, or threshold changes, append the old/new values, reason, approval source, timestamp, and whether the change followed exposure or result inspection. Treat post-result changes as exploratory and require a new prospective test for a confirmatory claim. Run the bounded bookkeeping checker, then use the next-decision guide; a valid JSON record does not prove demand.
