# Measure traffic and bottlenecks
Read [digest](../references/research/distillation.md), then fill the [worksheet](../references/templates/measurement-worksheet.md). Sources: monitoring, overload, SLOs.

1. Pin service/journey, environment, release/artifact, region, provider plan, observation UTC interval and source query/export. Use supplied aggregates or authorized existing read-only evidence. Record owner, known peak/burst duration and target recovery expectation. Ask once for missing material fields; retain unknowns.
2. Trace caller, cache, application, database/pool, queue consumer and external dependency. Capture each boundary's ingress/admitted/completed/rejected/timeouts and retries separately. State whether traffic includes assets, bots, internal calls or duplicate attempts. Per-user/tenant classes use permitted aggregates, never customer identifiers or raw payloads.
3. Record same-window count and sampling/filter/drop rules; histogram percentiles, timeout treatment, sample size, UTC resolution and ingestion delay. Sampled traces are not automatically population denominators. Route telemetry wiring or sampling changes to selected Sentry, preserving Security privacy decisions.
4. Gather CPU time/utilization with core denominator, memory/RSS/limit/OOM and event-loop or worker wait where available. Add DB active/max connections, pool wait p95, query p95, lock wait; queue depth/oldest age/arrival/completion/retry/DLQ rates; dependency latency/rate limit/429/timeout counts. Missing data lowers confidence; low CPU cannot exclude DB/pool saturation.
5. Compare matched baseline/peak windows and workload mix. State observed bottleneck, competing explanations and one additional measurement that would distinguish them. A shared downstream can saturate when frontend concurrency rises. No configuration follows from a diagnosis.
6. Separate OBSERVED target exports, DERIVED calculations, ASSUMED scenarios and NOT_RUN validation. Missing or stale telemetry cannot establish recovery. Provide exact aggregate evidence references and units.
