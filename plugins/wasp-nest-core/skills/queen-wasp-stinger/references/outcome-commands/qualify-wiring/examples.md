# Constructed wiring decisions

1. A specialist skill has no actual paired Drone. Source validator/roster inspection refuses source completion. It does not invent or activate a role as a repair.
2. A standalone personal skill declares its tier and has no Drone. Pair absence is valid. Direct skill loading still preserves action permissions and cannot fabricate an independent review.
3. A command validates and its generated source-command wrapper exists, but its optional owner is absent from the selected registry. The receipt records source/projection PASS and selected/native UNEXECUTED or blocked. A cached copy cannot satisfy selection.
4. Native Codex TOML parses with name/description/developer_instructions, while the running client has not discovered or invoked it. Parser PASS is carrier syntax only. Registration or hook trust is a separate authorized action; no release/runtime claim follows.
5. Canonical Markdown agent validation emits a host-format informational skip. The receipt preserves reduced coverage and inspects the generated host carrier; it does not print a universal native PASS.
6. A hook is present in the source package, but no trusted installed binding or actual event is observed. It remains unactivated/unexecuted. Source tests cannot authorize global settings writes.

These source cases are teaching artifacts. They are not observations of a user's installed host or proof of actual release behavior.
