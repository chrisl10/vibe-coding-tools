# Use the paired skill without inventing a native agent

Use for O289 when a requested skill exists but this session cannot dispatch its paired native role. Grounding: [digest](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/src/skills/harness-integration-stinger/references/research/availability-proof/distilled-availability.md). Fill [the fallback record](../templates/skill-fallback-record.md).

1. Resolve and read the actual selected paired SKILL.md and the required guides/resources. Source authoring may read canonical source explicitly; identify that mode and do not call it installed dispatch. Read the skill's scope, exclusions, effects, prerequisites and independent-review requirements before choosing a fallback.
2. State the missing surface and exact retained behavior: the current agent can follow the skill's procedure and produce a local draft within existing task authority. The fallback creates no worker identity, separate context, isolation, simultaneous execution or independent reviewer. A manually read Drone identity does not create a native agent.
3. Preserve the original task constraints, named approach, permissions, model inheritance, deadlines, retry limits and resource boundaries. Missing tools stay missing. A skill mention cannot create connector permission or grant send/install/activation authority. Resolve required optional owners before dependent work; do not copy helper code from an unselected pack.
4. If current capacity or supervisory tools are unknown, perform authorized serial preparation only. Keep existing AppPrimer briefs and receipts if they apply; a structural PASS does not launch workers. Do not simulate concurrency by silently splitting contexts or creating extra tasks.
5. If the task requires independent Security/Quality review, isolation or a native side effect, mark that requirement BLOCKED until a supported separately authorized surface is available. Self-review may find errors but cannot be relabeled as independent review. A different supported generic worker is a distinct possible dispatch, requiring verified capacity, explicit role instructions and retained evidence; it is not a named-role proof.
6. Deliver the retained artifact and list losses. Report native execution as UNEXECUTED. If the reduced behavior would change the user's requested result, ask once before that dependent work; continue unaffected preparation.

See [rendered fallback cases](../references/examples/availability-proof/O289-skill-fallback.md). This procedure degrades delivery honestly rather than manufacturing APIs or silently changing the requested architecture.
