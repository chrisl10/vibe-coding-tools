# Prove selected availability before dispatch

Use for O288. Start with [the digest](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/src/skills/harness-integration-stinger/references/research/availability-proof/distilled-availability.md), then fill [the receipt](../templates/availability-receipt.md).

1. Classify the claim: source coverage, package validation, installed selection, native discovery, execution or account access. Record host, carrier and version as observed or unknown. An ordinary source checkout can establish only source coverage and the checks actually run there.
2. Inspect the canonical catalog owner, component kind and required workflow. For source work use catalog source roots. For installed work use the trusted selected Core root and explicit registry. Do not crawl cache siblings or select a pack because its directory exists.
3. Run the existing Core resolver through an available runtime with explicit `--core-root`, `--registry`, `--kind` and, where needed, `--workflow`. Obtain actual paths rather than substituting an example root. See its [source](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/src/skills/harness-integration-stinger/references/research/availability-proof/raw/core-resolver.txt) for supported flags. Resolve the paired skill independently when the requested kind is agent. Missing prerequisite, identity/version mismatch, unknown workflow and missing resource block installed dispatch. Preserve the exact refusal and report what source preparation remains possible.
4. Inspect the returned resource and manifest version and record hashes for the inspected candidate. The resolver's JSON includes checked owners and component path; it does not return a native-enabled verdict. A UI install, registry selection, role projection and native discovery are separate receipts. Do not edit the registry or register roles during detection.
5. Check actual host tools/native inventory under current policy. Record names exactly as exposed; do not invent a discovery API, invoke an arbitrary shell command copied from another host or infer capacity from a config maximum. If a native observation surface is absent, mark discovery UNKNOWN and use the authorized [skill fallback](09-use-skill-fallback.md) if it meets the task contract.
6. Before a real operation, inspect scoped account/tool access separately. Read permission is distinct from write/send/delete permission; both are distinct from user authorization. Leave unavailable access UNKNOWN. Do not read secrets to fill a worksheet.
7. Report a qualified sentence, for example: “Core resolver accepted these selected owners and versions; native role loading has not been exercised.” Never shorten it to “installed and working.”

The existing `scripts/test_plugin_topology.py` InstalledRegistryTests can exercise refusal/selection behavior in temporary synthetic packages. These tests do not probe the actual host, install a plugin or prove that optional roles are enabled. No new availability scanner is needed.

See [rendered cases](../references/examples/availability-proof/O288-selected-availability.md). Detection is read-only; permission/configuration changes require their own authorization.
