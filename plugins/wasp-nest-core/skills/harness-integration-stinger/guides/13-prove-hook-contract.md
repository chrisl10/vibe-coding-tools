# Prove a hook contract on the actual host

Use for O292. Load the digest, [the source advisory procedure](component-validation-hook.md), then [the hook receipt](../templates/hook-contract-receipt.md).

1. Identify purpose: advisory observation or intentional authorization/integrity gate. Record host version, carrier, selected owner version, handler hash, registered event/matcher, root substitution, interpreter, trust decision and permission scope. Unknown fields stay UNKNOWN; source settings do not prove active settings.
2. Obtain a redacted event-specific native payload through an authorized observation surface. Record actual nesting, types, path semantics, cwd and stdin/transport. Never copy transcript content, tokens or personal data into a fixture. Unsupported or absent payload/event is a gap, not successful degradation.
3. Inspect parser and invocation against that payload. Record exact recognized inputs and rejects, argument construction, cwd/root assumptions, called validators, effects, response JSON and exit-code contract. The existing handler recognizes nested tool_input/toolInput path fields or patch command headers; a direct top-level path is not presently parsed. Cursor response inference is not proof of host identity.
4. Exercise existing scripts/test_component_validate_hook.py offline: malformed metadata, oversize, types, deduplication, unknown owner, target overflow, subprocess failure/output/privacy/timeout. These fixtures use temporary synthetic roots and establish handler behavior only. Do not activate a hook for an offline test.
5. Record handler input/output limits and host deadline separately. Current handler input is bounded to262144 bytes; targets to20; validator output to65536 bytes; remaining subprocess budget is4000 ms. These do not time out stalled stdin, prove host termination, bound native scheduling, or enforce a permission decision. A timeout/unavailable check is unverified.
6. Under separately authorized native execution, bind request/event/payload hash, handler version, runtime version, result and failure to an observed receipt. Confirm client accepts the emitted shape and actual permission/trust behavior. Never treat empty JSON as a successful recognized validation without invocation evidence.
7. Compare carriers explicitly. Current source Claude plugin has component validation PostToolUse; Cursor native plugin only has sessionStart, though home Cursor declares postToolUse; OpenAI plugin only declares SessionStart registration. Inspect the built artifact before any host claim. Preserve/translate/degrade/drop must name the retained behavior and lost timing/decision surface. A source script cannot make an unwired event native.

No universal event-count floor or blanket fail-open policy applies. Advisory errors preserve observation semantics; intentional gates preserve denial semantics. This procedure changes no live settings or permissions.
