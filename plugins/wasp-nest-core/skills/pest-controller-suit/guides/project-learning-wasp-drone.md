# Project learning routing guide

**Owner:** developer-learning-tools. Requires selected Core and this owner.

## Domain and triggers

Learn HTML, CSS and JavaScript with a small project; choose a learning path from current knowledge; give me an exercise and feedback. Also route preparation of one exercise, teach-back and criterion rubric from an explicitly supplied technical source/revision. The output links source claims and expected observable responses to actual attempts, support, changed conditions and teach-back, with PENDING or UNSUPPORTED where evidence is absent.

## Boundaries

Project Learning prepares source-linked practice; Core Knowledge supplies repository facts and Technical Explainer preserves faithful explanation. Resolve the selected subject owner before domain interpretation; a missing owner stays UNSUPPORTED. The existing web fundamentals curriculum remains bounded. A criterion rubric is formative evidence for this exercise, not a validated scoring scale, competency or certification. Technical Explainer explains supplied sources. Builder Readiness prepares product expectations. Selected implementation owners build products. This pair does not own broader debugging, testing, security, stack choice or career forecasts. It uses synthetic practice data and current tools, with no install, customer-system writes, settings changes, publishing or automatic learning-record storage.

## Dispatch

Resolve project-learning-stinger through trusted Core's selected registry before arming it. Source work uses its canonical catalog owner. A source or cache path does not prove an installed capability. Report native delegation or authorized direct use honestly. The paired role is read-only; an authorized orchestrator can save a new scoped exercise file. No real learner response means understanding PENDING.
