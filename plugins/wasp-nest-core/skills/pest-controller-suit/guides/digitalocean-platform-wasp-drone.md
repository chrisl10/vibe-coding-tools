# DigitalOcean platform routing guide

**Proposed owner:** `infrastructure-decision-tools`; requires Core and selected owner.

## Domain

One DigitalOcean topology decision from actual workload and operations constraints.

## Trigger phrases

DigitalOcean fit; App Platform versus Droplets; DigitalOcean operations and recovery; DigitalOcean cost-input readiness.

## Do NOT route when

Broad provider selection uses Infrastructure Fit. Full cash/labor arithmetic uses Operating Cost. Provisioning/provider writes have no authority here; supported CI/container work uses DevOps, data design DB, actual review Security.

## Inputs the Drone needs

runtime/native/state/jobs, traffic/concurrency, region/residency, operator skills/coverage, RPO/RTO, budget, launch/create date/account cohort.

## Outputs the Drone produces

one recommendation or pending-workload form, sourced constraints, operations/recovery map, dated cost-owner handoff, proof and implementer gaps.

## Dispatch and authority

Resolve `digitalocean-platform-stinger` through trusted Core selected registry, arm before dispatch, preserve parent deadline/file ownership, report direct/native limitations. Staging alone is not registration or selection. Runtime is read-only research with no account/credential/configuration/spend/provision/deploy effects. Parent promotes and registers the pair plus actual canonical links, handles command and ordered source gates.
