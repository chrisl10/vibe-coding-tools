# go-desktop-wasp-drone

**Plugin owner:** backend-and-desktop-tools. **Required selection:** wasp-nest-core. Optional web-development-tools only for frontend implementation. Resolve the selected installed owner/prerequisites before dispatch; source availability does not establish installed selection.

## Domain

Explicitly chosen Wails v2 desktop application with a Go backend: app options, generated web bindings/DTOs, narrow facade validation, lifecycle/jobs/storage integration and actual native/package evidence.

## Paired Stinger

[go-desktop-stinger](https://github.com/legioncodeinc/vibe-coding-tools/blob/main/plugins/backend-and-desktop-tools/skills/go-desktop-stinger) owns the exact procedure, dated sources and evidence limits.

## Trigger phrases

- "build a desktop app around this Go backend using Wails v2"
- "implement Wails bindings and lifecycle"
- "qualify this Wails desktop build"

## Do NOT route when

Only Go language preference is supplied: ask for the framework decision. General Go modules/services -> go-wasp-drone. Existing Tauri/Electron with Go sidecar -> existing shell owner plus Go worker. Wails v3/Fyne/mobile -> unsupported by this pair, require its own owner/contract. UI/schema/provider/security/dependency/CI/publication work stays with its peer.

## Inputs

Accepted Wails v2 decision, repository/owned files, native OS/architecture and first journey, actual dependency/toolchain graph, frontend/bridge/storage contracts and exact authorized effects. Missing trust-changing decisions block dependent implementation.

## Outputs

Bounded Wails slice and consumer library evidence report with exact bridge inventory, target/build artifacts and hashes, native refusal/lifecycle/storage/package observations and explicit NOT_RUN gaps. No installation, real file mutation, credentials, signing or publication authority follows from dispatch.

## Required sequence

Paired skill -> current inspection -> accepted bridge -> bounded implementation -> authorized checks/native evidence -> independent Security -> affected reruns -> Quality -> parent repository health -> user review and approval before commit/push.
