# infrastructure-fit routing guide

**Plugin owner:** `infrastructure-decision-tools`. Requires Core and this selected owner.

## Domain

Recommend one topology from workload, budget, operator skills and sourced constraints.

## Trigger phrases

choose infrastructure; managed vs VPS; hosting fit; operator responsibilities.

## Do NOT route when

Provisioning, live configuration, provider price guesses and cost arithmetic are separate owners.

## Inputs the Drone needs

normalized runtime/workload, data, geography, budget, operator and recovery constraints.

## Outputs the Drone produces

one sourced topology recommendation, responsibilities, unknown costs and reassessment triggers.

## Dispatch and authority

Resolve `infrastructure-fit-stinger` through trusted Core's selected registry before dispatch. Source work uses the current catalog owner and canonical path. A cache is not an enabled capability. Arm the selected skill first, preserve the parent's clock/ownership, and report actual direct/native execution support. The runtime is advisory preparation: it does not create accounts, change live settings, accept contracts, spend or publish. Code changes close Security then Quality and the orchestrator repository-health gate.

[Source skill](https://github.com/legioncodeinc/vibe-coding-tools/blob/main/plugins/infrastructure-decision-tools/skills/infrastructure-fit-stinger/SKILL.md) and [paired Drone](https://github.com/legioncodeinc/vibe-coding-tools/blob/main/plugins/infrastructure-decision-tools/agents/infrastructure-fit-wasp-drone.md) carry the exact procedure and selected-owner handoffs.
