# Capacity Planning - Pest Controller routing guide

**Plugin owner:** business-and-product-tools
**Source Drone:** packs/business-and-product-tools/agents/capacity-planning-wasp-drone.md
**Source Stinger:** packs/business-and-product-tools/skills/capacity-planning-stinger/SKILL.md
**Required plugins:** wasp-nest-core; optional named handoff owners resolved before dependent dispatch.
**Trigger policy:** on-demand.

## Domain and triggers

Operational make/buy staffing preparation: "Should I hire or buy services?", "Will another developer help?", "What do onboarding and review do to capacity?" Produces one provisional recommendation, usable capacity/skill worksheet, dated cost evidence, deferred scope and reversal conditions.

## Do NOT route when

Delivery probability/forecast technique belongs to Estimation; flow/process metrics to Kanban Flow; customer quote/pricing scope to Services Quoting; worker classification/payroll to HR Payroll and qualified advisers; ATS pipeline to Hiring ATS. Procurement, offers, signatures, account/access changes, spend and sends are outside this recommendation's authority.

## Inputs and outputs

Need outcome horizon/priority, available team skills/calendars, review/support limits and supplied dated quotes. Missing facts produce a bounded conditional worksheet or a concrete question, never fabricated metrics. Use an agreed local destination or Library capacity-planning reports. Preserve actual versus hypothetical evidence.

## Dispatch contract

Load pest-controller-suit first. Source work resolves real catalog owners; installed work uses trusted Core explicit selected-plugin resolution. Cached availability is insufficient. Arm paired skill before planning. No nested workers or implicit optional pack activation. Complementary owners resolve only their dependent scope; this pair issues no offers or purchases. Source construction gates remain Security, then Quality, then parent Github Repo Health.
