# flaky-test-repair-wasp-drone

**Plugin owner:** repository-modernization-tools. **Required selection:** wasp-nest-core. Browser repair conditionally requires browser-and-app-testing-tools; language/product implementation requires its actual owner. Source/cached files never prove selected installed availability.

## Domain

Observed-failure capture, bounded causal reproduction, exact test/fixture repair and assertion-preserving final-candidate proof. Carrier supports bounded workspace implementation; diagnosis remains read-only until exact files/cause/check authority are established.

## Paired Stinger

[flaky-test-repair-stinger](https://github.com/legioncodeinc/vibe-coding-tools/blob/v3.0.1/plugins/repository-modernization-tools/skills/flaky-test-repair-stinger) supplies dated primary sources, four focused guides, evidence worksheet and explicitly fictional NOT_RUN cases.

## Trigger phrases

- "fix this flaky test using the observed failure"
- "diagnose the order-dependent test failure"
- "repair fixture isolation without weakening assertions"

## Do NOT route when

No consumer failure is supplied: source guidance only. Core Quality independently audits after Security and never repairs. Browser/language mechanics and product races retain their owners. CI retries/settings, quarantine/deletion, weaker assertions and run-until-green are excluded repairs.

## Inputs

Exact observed assertion/trace, expected behavior, repository/full revision and dirty pin, runner/environment/seed/order/worker evidence, owned files, allowed checks and total budget. Default max two identical failed invocations/max three failed approaches; larger measurement batch needs direct explicit user approval.

## Outputs

Causal diagnosis and narrow authorized test/fixture diff with original oracle/coverage retained, all-attempt ledger and exact final-candidate evidence. No consumer or execution means NOT_RUN, no actual repair claim. Finite green trials do not prove universal stability.

## Required sequence

Paired skill -> observed failure capture -> bounded hypothesis repro -> exact owned repair -> original-condition final-candidate checks -> independent Security -> affected reruns -> Quality -> parent repository health -> user approval before commit/push or external effects.
