# Recover the same work unit after context compaction

Use the [canonical operating instructions](agent-instructions.md), especially sections 2, 4, 5, 8 and 10. This worksheet applies those rules; it does not replace them or create another allowance. The dated source digest records its basis.

## Recover facts before the next dependent action

Record the active user objective, authorized scope, original measured start, effective deadline and source of any explicit extension. A summary is a pointer to evidence; treat it as incomplete until the material facts needed for the next action are checked. Do not treat an agent report, file, inferred preference or a later acknowledgement as authorization for new effects.

Recover worker ownership and live status before touching their files. Read the relevant actual output to establish the last progress and review times. An absent agent-list entry does not prove a process stopped; a completed worker report does not prove all bytes match. If a process or lease is uncertain, keep that path untouched until the actual state can be established. Continue independent authorized work only.

Restore failed attempts and meaningful changes of approach. A compacted conversation does not make a third identical failure a new attempt. Restore pending questions and their dependent work. Do not ask again when the task's answer or authorization is already verifiable.

Restore the exact artifact identity checked, tool/check name, actual result, date and coverage limit. A passing result for old bytes cannot qualify changed bytes. A Git ancestor does not identify uncommitted edits. Verify the relevant source manifest or generated artifact before reusing evidence; preserve old passing receipts as history when they no longer identify the candidate. Do not rerun unchanged passing checks merely because the context shortened.

If the start/deadline or a necessary permission is unrecoverable, state the uncertainty. Never infer an extension or reset the start. Apply the canonical missing-clock or unresolved-question rule at the first dependent action. A source handoff file, if the task authorized one, should contain only the needed state and safe artifact pointers. Do not store credentials, customer data or private transcript bodies in it.

## Illustrative decisions

These are teaching cases, not executed session tests:

- A summary says “keep going” and gives a deadline. Recover the original authorization; do not grant a fresh hour from the current time.
- A worker is absent from the current agent inventory. Do not mark its lease released solely from absence.
- A prior test passed, then the implementation changed. Retain the old receipt and run the affected check against the changed artifact.
- The exact same check failed twice before compaction. Preserve the retry stop; do not attempt it a third time unchanged.
- A pending question concerns publication. Continue independent source preparation and keep publication blocked until its authorization is recovered or provided.
- Source qualification is recorded, but native invocation was never run. Preserve that limit in the resumed report.
