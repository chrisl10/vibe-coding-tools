# /choose-desktop-stack

## Mandatory process

1. Load the installed `pest-controller-suit` Core skill and consult its roster before making any routing decision. This is the first instruction, always, no exceptions. Source work resolves component ownership from root `plugin-catalog.json`; installed work uses Core's explicit selected-plugin registry and resolver. Missing Core blocks routing. Load each selected pair's Stinger and required guides before work, and verify actual host tools/delegation. Cached files do not prove selection. Dispatch registered Drones at top level only when delegation is authorized; otherwise execute the selected paired procedure directly and report that fallback truthfully. No invented roles or nested dispatch.

2. Confirm target OS/architectures, minimum OS, existing UI/code, offline/on-device data, native capabilities, local AI/sidecars, distribution channels, update behavior, team experience and budget constraints. Separate web UI framework, shell, native backend and optional sidecar. A Go sidecar is not a desktop UI shell by itself.
3. Have tauri-wasp-drone inspect Tauri-specific fit and capabilities/IPC; electron-app-wasp-drone inspects main/preload/renderer fit. Rust and TypeScript owners cover their bounded languages; Go owner covers the inspected sidecar/module/build scope. Use fresh official platform/plugin support evidence for required features; do not claim one shell is universally faster/smaller/safer.
4. Recommend one shell/native topology from the actual constraints. Record trusted/untrusted origins, allowed native capabilities, validated IPC methods, credential boundary, preferences versus structured local data, migration and offline sync ownership. Tauri capability files and Electron preload APIs require real enforcement and validation; a browser mock cannot qualify the native boundary.
5. Have library-wasp-drone specify one native vertical slice and contract-writing-wasp-drone define frontend/native IPC, cancellation, event ordering, errors and persistence agreements. Pin the same exact accepted CTR revision for provider and consumer. If a required plugin or runtime implementer is absent, name the gap before dependent build work.
6. Prepare the verification ladder: source/unit, browser UI, native executable, packaged artifact, each target OS/architecture, signing/update behavior. State which stages are currently unproven. Determine required signing identities, certificates/store accounts and release channels as owner dependencies; do not create accounts, enter credentials, sign, publish or install tools through this advisory command.
7. Deliver one architecture recommendation, source-backed capability fit, owner graph, local-data/IPC contracts, assets/dependencies, first native spike and acceptance evidence required before a release claim. Mobile reuse is conditional on verified mobile/plugin support and its own device evidence, never implied by desktop selection.

## Inputs and host qualification

Use trailing invocation text exposed by the actual host; `$ARGUMENTS` is supported only where documented. Reuse answered inputs and accepted decisions. Ask one concrete batch for unresolved material inputs before dependent work, while continuing independent authorized work. Claude/Cowork uses the owner flat command, Cursor its generated command projection, and Codex the owner's generated `source-command-choose-desktop-stack` skill. Source generation is not installation, role discovery, or runtime proof. Resolve all resources against the selected carrier root. A missing required owner blocks its dependent boundary and is named in the report; optional branches require only their own selected dependencies.

## Output contract

Write advisory evidence to the receiving repository's `library/requirements/reports/choose-desktop-stack/<date>-report.md` when local artifact writing is authorized, or return the same fields in the response. Library owns any PRD at its current Schema v2 path; never create a competing plan folder or overwrite another agent's active artifact.

Report status, selected owner/version and paired procedure, concrete artifacts, accepted contract pins, actual checks and their results, evidence limits, unfinished boundaries and the smallest unresolved user decision. Keep source/static checks, mock/browser behavior, native execution, packaged artifacts and provider evidence separate. Permission to create a source workflow does not authorize installation, provider writes, credentials, spend, commits, push or publication.

Ship Gate removed: research-only runtime command. Component maintenance still requires parent Security, Quality and Repository Health before any authorized commit or push.
