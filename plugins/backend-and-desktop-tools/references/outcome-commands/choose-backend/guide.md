# Workflow guide

1. Load the installed `pest-controller-suit` Core skill and consult its roster before making any routing decision. This is the first instruction, always, no exceptions. Source work resolves component ownership from root `plugin-catalog.json`; installed work uses Core's explicit selected-plugin registry and resolver. Missing Core blocks routing. Load each selected pair's Stinger and required guides before work, and verify actual host tools/delegation. Cached files do not prove selection. Dispatch registered Drones at top level only when delegation is authorized; otherwise execute the selected paired procedure directly and report that fallback truthfully. No invented roles or nested dispatch.

2. Confirm workload shape, frontend boundary, existing code, team experience, required libraries, concurrency/jobs/realtime needs, deployment target and operational capacity. Separate backend language, HTTP framework, datastore and hosting decisions. Preserve an existing stack unless a change is explicitly in scope.
3. Read selected python-wasp-drone, go-wasp-drone, rust-wasp-drone and typescript-node-wasp-drone paired procedures before assessing ownership. Python covers Django/FastAPI and their boundaries; Go's pair focuses module/toolchain/vendor/build mechanics and is not automatic whole-product backend coverage; Rust covers bounded Cargo/Tokio/Axum/SQLx work; TypeScript/Node coverage must match the actual service/framework. Do not make universal throughput, memory or AI-productivity claims.
4. Compare viable candidates against the same workload and required integrations using fresh official docs at the decision date. Separate measured project evidence from architectural hypotheses. Eliminate candidates whose missing libraries/platform limits or maintenance demands violate the stated constraints, with a cited reason.
5. Recommend one language/runtime and its supported implementation owner. Record HTTP/auth/data/job boundaries and security-review coverage. A missing server/framework specialist or formal audit remit is an explicit gap; choosing a language does not fill it. If no available owner can implement the required boundary, deliver a provisional recommendation and name the blocked decision.
6. Have library-wasp-drone prepare the accepted architecture requirements and contract-writing-wasp-drone identify provider/consumer API/event/data agreements. Record exact already-accepted CTR revisions; unresolved ones stay Draft. ADR authorship, when needed, routes to selected Core adr-writing-wasp-drone rather than being mislabeled a language deliverable.
7. Deliver one recommendation with workload rationale, retained constraints, actual owner graph, version evidence date, small validation spike and unresolved risks. This advisory command does not scaffold code, install packages, switch infrastructure or start provider jobs.

## Inputs and host qualification

Use trailing invocation text exposed by the actual host; `$ARGUMENTS` is supported only where documented. Reuse answered inputs and accepted decisions. Ask one concrete batch for unresolved material inputs before dependent work, while continuing independent authorized work. Claude/Cowork uses the owner flat command, Cursor its generated command projection, and Codex the owner's generated `source-command-choose-backend` skill. Source generation is not installation, role discovery, or runtime proof. Resolve all resources against the selected carrier root. A missing required owner blocks its dependent boundary and is named in the report; optional branches require only their own selected dependencies.

## Output contract

Report status, selected owner/version and paired procedure, concrete artifacts, accepted contract pins, actual checks and their results, evidence limits, unfinished boundaries and the smallest unresolved user decision. Keep source/static checks, mock/browser behavior, native execution, packaged artifacts and provider evidence separate. Permission to create a source workflow does not authorize installation, provider writes, credentials, spend, commits, push or publication.
