# Qualify a macOS release candidate

Use for O097. Read [the dated digest](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/native-release-20261007/distilled-native-release.md), then refresh Apple/Tauri documentation before a real release. This is a DERIVED procedure.

1. Ask for supported macOS versions, Intel/Apple Silicon targets, delivery route (Developer ID outside the Store or Store), updater route, and persistence compatibility. Record unknowns instead of guessing.
2. Inventory the exact app bundle, nested code, sidecars, frameworks, installer/container and update archive. Bind every result to source revision, target triple, toolchain, resolved dependency graph and final artifact SHA-256.
3. Identify the signing identity type and owner without opening private keys. Developer ID and ad-hoc signing serve different acceptance paths. OS code signatures establish code identity/integrity; notarization adds Apple's service assessment and ticket. Store review is a separate route. [Apple](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/native-release-20261007/raw/apple-notarization.md), [Tauri](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/native-release-20261007/raw/tauri-macos-source.md).
4. Prepare protected CI secret NAME references only: `APPLE_SIGNING_IDENTITY`, `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`; notarization may use `APPLE_API_ISSUER`, `APPLE_API_KEY`, `APPLE_API_KEY_PATH` or `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID`. The credential owner chooses and configures one approved authentication route. Never print, read, export or provision values as part of this planning procedure. [Tauri](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/native-release-20261007/raw/tauri-macos-source.md).
5. For an already authorized and produced candidate, inspect signature identity/entitlements, notarization request status and log, and ticket attachment. Submission, signing and stapling are separately authorized mutations. A submission ID alone is insufficient; require accepted status and review warnings. [Apple workflow](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/native-release-20261007/raw/apple-customize-notarization.md).
6. Use the existing native tooling only if available. Suggested read-only checks, with literal owner-supplied paths: `codesign --verify --strict --verbose=2 /path/to/App.app`, `codesign -dv --verbose=4 /path/to/App.app`, `xcrun stapler validate /path/to/App.app`, `spctl --assess --type execute --verbose=4 /path/to/App.app`. Capture sanitized output and OS/tool versions. These checks do not replace actual first-launch testing or nested-code inspection.
7. Track a stapled bundle separately from its packaging. ZIP cannot itself be stapled. Repackaging after stapling changes bytes, so compute final delivery/update hashes after authorized transformations. [Apple workflow](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/native-release-20261007/raw/apple-customize-notarization.md).
8. Have the release owner test the downloaded/quarantined delivery route on each supported architecture and OS, including offline ticket discovery, install/first launch, sidecar launch, permissions and uninstall. Never remove quarantine or advise disabling Gatekeeper to convert a failed release into a pass.
9. Fill [the qualification template](../templates/native-release-qualification.md). Updater signature evidence remains separate; define data-safe recovery before claiming rollback. Run Security then Quality, then the parent repository-health gate. Publication remains a separate owner action.

A local command returning success proves only the check on those bytes in that environment. All absent native checks stay OPEN. [Apple](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/native-release-20261007/raw/apple-notarization.md).
