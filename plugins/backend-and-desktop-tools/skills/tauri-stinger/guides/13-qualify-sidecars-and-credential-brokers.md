# Qualify sidecars and credential brokers

Use for O103. DERIVED implementation procedure grounded in [sidecar](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/desktop-capabilities-20261007/raw/sidecar-source.md), [shell](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/desktop-capabilities-20261007/raw/shell-source.md), [capabilities](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/desktop-capabilities-20261007/raw/capabilities-source.md) , [shell reader](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/desktop-capabilities-20261007/raw/shell-process-source.md) and [Stronghold](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/desktop-capabilities-20261007/raw/stronghold-source.md). No current package version is implied. Complete the [record](../templates/desktop-capability-evidence.md) under the consumer repository report path.

1. Inspect the resolved Tauri/plugin graph, binary targets, bundle.externalBin entries, capability selection and custom command manifest before implementation. Identify every window and remote origin. Scope review is about the effective union, including other capability files.
2. Draw the boundary as webview -> narrow application command -> Rust authorization -> exact executable -> typed protocol -> bounded result. Rust-owned spawn removes the need for frontend shell grants but is not automatic business authorization; validate inputs again in the command.
3. Pin executable identity by named target, hash, provenance and platform signature requirements. Resolve the packaged executable; never accept a caller-supplied program, shell fragment, environment dump or replacement search path. Keep arguments fixed or from bounded, domain-specific enums. If frontend spawn is truly required, permit the exact sidecar, method and argument shapes separately; do not add args:true or arbitrary sh -c.
4. Define protocol framing, schema/version, correlation IDs, readiness, stdout/stderr and per-operation/total-byte limits before process launch. Use raw chunks with a bounded accumulator or a producer with enforced line limits. A size check after a full-line event does not bound upstream allocation. Sidecar protocol semantics belong to the relevant protocol/language owner.
5. Own child handle, reader task, startup deadline, operation deadline and cancellation in one lifecycle record. Require bounded shutdown and evidence that descendants and reader tasks terminate. Killing one handle alone is not proof of process-tree cleanup. Declare crash/restart semantics and preserve partial output; never silently replay paid or state-changing work.
6. Classify credential ownership. Publisher credentials stay at a publisher-controlled service. User credentials may be used through an approved OS/vault boundary; frontend receives an opaque reference and safe status, never a retrieved key. Stronghold frontend retrieval grants defeat that intended boundary even if the vault is encrypted at rest.
7. Prefer a Rust broker that performs the credential-dependent operation itself. If a sidecar genuinely needs a user secret, review the smallest authenticated local transfer, lifetime, process access and destruction limits with Security. Do not pass secrets in argv, logs, inherited environment dumps or unbounded stderr; local users/processes remain in the threat model. No claim of zeroization follows from dropping a String.
8. Qualify allow and deny paths on actual packaged targets: wrong window/origin; unknown sidecar/argument; malformed/oversized frames; wrong correlation; startup timeout; crash; cancellation; vault lock/revocation; reload; exit; log redaction. Use synthetic canaries rather than real keys. Bind results to binary hashes and platform. Native checks stay OPEN here.

Stop for unknown credential owner, process privilege, protocol contract or target. The Rust/language owner implements process internals; Security accepts the boundary, then Quality reviews the outcome. A JSON schema pass closes only document shape.
