# Qualify safe export

DERIVED O105 procedure. Read [the digest](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/file-safety-20261008/digest.md) and record [evidence](../templates/file-safety-evidence.md). Export permission, overwrite permission and backup retention are separate approvals.

1. Freeze the export schema, data selection/redaction, destination selection, maximum output size and exact overwrite policy. Bind a Rust-owned token to the initiating window, parent directory identity, intended filename and action. Inspect custom scope enforcement and effective capability union as in [import](18-qualify-local-import.md). A save-dialog selection does not authorize unrelated replacement or cleanup.
2. Validate destination components, existing ancestor identities and target file type using target-native semantics. A new destination cannot be fully canonicalized; verify and retain its existing parent handle and validate the leaf. Reject unsupported symlink/reparse/hardlink cases. A path existence check does not prove no-overwrite safety.
3. Build the output from a frozen app snapshot. Create a unique app-owned temporary regular file in the qualified destination directory using exclusive creation and safe permissions. Never truncate the final destination to stage an export. Verify the retained handle, bound output and check every write/serialization error. [Exclusive creation](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/file-safety-20261008/raw/rust-options-source.md).
4. Flush application buffers, synchronize the file through the qualified OS primitive, handle errors and close/finalization requirements. Publish using a primitive qualified for the requested policy. Ordinary Rust rename replaces an existing file: do not emulate no-overwrite with exists then rename. Select a target-supported atomic no-replace mechanism or stop for the Rust/OS owner. [Rust rename](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/file-safety-20261008/raw/rust-rename-source.md).
5. For approved overwrite, bind approval to the exact prior destination identity/content revision. Ensure the chosen operation actually enforces that precondition at commit, including concurrency policy; a second metadata check alone does not close the race. Define and verify a protected backup before replacement when required, including recovery identity, hash, retention and sensitive-data policy. If the platform cannot provide the required concurrency guarantee, fail closed.
6. Same-filesystem publication may provide atomic namespace visibility on a qualified target. Cross-volume rename fails; do not silently replace it with copy-and-delete. Obtain approval for a separately qualified copy workflow if needed. Directory synchronization and storage/device semantics need OS/filesystem-specific evidence. Atomic rename, sync_all success and buffered flush are distinct; none alone certifies power-loss durability. [POSIX](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/file-safety-20261008/raw/posix-rename-source.md), [File sync](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/tauri-stinger/references/research/file-safety-20261008/raw/rust-sync-source.md).
7. Record operation stages: draft created, bytes verified, sync result, destination published, directory persistence result and outcome confirmed. Before publication, failure preserves the prior destination. After publication but before durability confirmation, report published durability-unconfirmed; reconcile exact identities rather than retrying or restoring blindly. Cleanup is limited to identity-verified temporary files created by this operation. Never delete a matching name alone.
8. Report output schema, size/hash, destination reference, overwrite approval, prior revision/backup reference and exact achieved durability level. Keep private content and raw paths out of default telemetry. Require authorized real-target tests for disk full, permission denial, changed destination, symlink/reparse races, locks, cross-volume publication, cancellation and process/power interruption. Constructed examples are NOT_RUN.
