# Inspect and scope the Wails desktop boundary

Read [the digest](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/go-desktop-stinger/references/research/digest.md). This is a DERIVED procedure for explicitly selected Wails v2, not a substitute for an unresolved framework choice.

1. Preserve the user request, current repository/branch and active ownership. Obtain supported OS/architecture, first user journey, existing Go backend boundary, frontend decision, offline/storage policy and intended package route. Missing Wails selection or a trust-changing decision blocks dependent implementation. No target supplied means planning/source evidence only.
2. Inspect existing main.go, app options, Bind/EnumBind, lifecycle hooks, AssetServer handlers, remote origins/navigation, generated wailsjs and frontend assets. Inventory all public methods on each bound struct. Record side effects and delegates. [Architecture](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/go-desktop-stinger/references/research/raw/wails-architecture-source.md).
3. Inspect go.mod/go.sum/go.work/vendor, actual module replacements, installed CLI identity, Go/toolchain env and frontend manifest/lockfiles. Record resolved Wails module/CLI and platform versions, never promote this documentation tree to an installed/latest version. Go commands can auto-download; inspect files first and require an approved network/toolchain policy before graph commands. [Toolchain](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/go-desktop-stinger/references/research/raw/go-toolchain-source.md).
4. Read the exact installed CLI help and official requirements for the selected versions. On authorized consumer hosts, `wails doctor` diagnoses prerequisites; it does not authorize dependency installation. Windows WebView2, macOS tools and Linux GTK/WebKit/cgo prerequisites are target-specific. Missing tooling is a concrete gap, no automatic installer fallback. [Setup](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/backend-and-desktop-tools/skills/go-desktop-stinger/references/research/raw/wails-setup-source.md).
5. Record the [worksheet](../templates/desktop-app-evidence.md), exact files owned by shell, Go services, frontend and release peers. Preserve an existing app; if scaffolding is approved, generate only into an approved empty destination with reviewed template/CLI options. Remote templates, package downloads, git initialization and overwritten files need their explicit authority. Do not run a generic init command across an existing backend.
6. Define the first slice and accepted bridge/storage contract before edits. Use [binding](02-bind-and-validate.md), [lifecycle](03-own-lifecycle-and-storage.md) and [native verification](04-build-and-qualify.md). Migration to v3 or an alternative desktop shell stops for its separate owner/contract.
