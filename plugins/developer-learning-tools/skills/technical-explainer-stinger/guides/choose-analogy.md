# Choose and bound an analogy

1. Ask for a familiar theme only if it materially improves understanding. Use an ordinary shared setting when no theme is supplied; avoid a sport or idiom the reader may not know.
2. Draft the factual relationship first. Select one analogy world and map each important source actor to one counterpart. Keep those names throughout the explanation.
3. Map the relationship being taught, not every technical detail. A library borrower can illustrate a request; a desk worker can illustrate a server. Neither establishes how an actual server is deployed.
4. Preserve permission boundaries. A library card can illustrate identity, while borrowing rules illustrate authorization. Possessing the card does not mean the borrower may take restricted records.
5. State the specific limit beside the analogy. For example, a network request is data rather than a person walking, and a server can handle many requests through mechanisms this example does not describe.
6. Remove the analogy if it requires more explanation than the original or implies a false rule. Keep the factual explanation so the reader can discard the metaphor without losing meaning.
