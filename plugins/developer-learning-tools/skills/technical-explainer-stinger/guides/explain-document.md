# Explain a document or post

1. Identify the exact source and one question the reader wants answered. Use supplied audience context; ask only missing material context. Default to grade-8 English when the user requested simplification. If translation is requested without a target language, ask for that language before translating.
2. Read the relevant source, including adjacent definitions and qualifications. For a post, separate the author's claims from supporting evidence. A linked article not retrieved is unavailable evidence. Stop at inaccessible material and ask for an accessible excerpt instead of guessing.
3. Build the [ledger](../references/templates/source-to-claim-ledger.md). Preserve modal verbs: may is not will, required is not implemented, proposed is not approved. Identify every actor, permission, condition and dependency that matters.
4. Draft in Diataxis Explanation mode. Lead with meaning, then explain relationships and consequences. Keep one worked example and the glossary. The source can be a tutorial or reference without turning the output into that mode.
5. Apply the [analogy guide](choose-analogy.md), then the [fidelity gate](../references/terminology-and-fidelity.md). Replace complex phrasing, not the underlying rule. Use the packet template and a reader-accessible source list.
6. Use [verify-understanding](verify-understanding.md). Leave reader understanding pending when there is no response. Do not publish or send the explanation unless the task explicitly authorizes it.
