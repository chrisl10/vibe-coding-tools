# Run one small project lesson

Teach one visible behavior with prediction, practice and feedback.

1. Confirm the agreed practice goal, current tools and writing/execution permission. Use [choose learning path](choose-learning-path.md) to identify the starting topic. If tools cannot open local files, deliver the lesson in chat and mark execution NOT_RUN. Do not replace the user's product files with an exercise.
2. Fill a [lesson card](../references/templates/lesson-card.md). Keep one HTML structure task, one CSS change or one JavaScript behavior per checkpoint. Explain the current term in plain language before using it. An element is one named part of a page; an event is a signal such as a button click.
3. Present the [tiny counter tutorial](../references/examples/tiny-counter-tutorial.md) one checkpoint at a time. Ask the learner to predict the result before trying. Wait for their attempt. Do not invent a response or silently complete their exercise.
4. Give feedback tied to the actual code or answer. State one thing that matches the expected behavior and one concrete correction if needed. Offer a hint before the full solution; honor a request for a worked solution. Label copied solutions as assisted.
5. Ask for a retry, then change one requirement for transfer. For the counter, change the step from one to two or add an explicitly scoped reset action. The learner's actual result, support and explanation determine the next lesson, not the tutor's satisfaction.
6. Use [review learning evidence](review-learning-evidence.md). Report code execution separately from browser observation and understanding. A local page is a practice artifact, not a deployed, persistent or production-ready application.
7. If the user shifts to product implementation, hand off the accepted behavior and evidence to the actual selected implementation owner. Defer broad debugging, testing strategy, security review, stack choice and readiness interviews to their existing owners.

Grounding: [digest L03-L09](../references/research/distilled-project-learning.md). Prediction and feedback sequencing is Wasp Nest teaching policy. No retention or learning-speed claim is made.
