# Choose a path from an observed baseline

Recommend one starting topic from the learner's goal and an actual small attempt.

1. Read the supplied context. Ask only missing questions: “What would you like to make first?” and “What have you already changed or written yourself?” Confirm whether a browser and text editor are already available. Do not install or create accounts as part of a lesson.
2. Separate reported experience from evidence in the [learning record](../references/templates/learning-record.md). Ask permission before saving learning records. Do not infer a path from age, language fluency, job title or confidence alone.
3. Offer one brief baseline appropriate to the goal: identify a heading and button in HTML; predict a CSS color change; or predict the counter after two clicks. Invite “I haven't tried this yet” as a valid answer. If the learner declines, give a provisional path and label it unassessed.
4. Compare the attempt with the expected behavior. If the learner cannot locate the file or open it, start with a file-and-browser task. If structure is unfamiliar, start with one HTML card. If HTML is understood but styling is unfamiliar, add one CSS change. If both are observed, start with the JavaScript event exercise. A developer from another language can begin with DOM concepts after showing structure and styling knowledge.
5. Recommend ONE next exercise and state why its prerequisite is supported or uncertain. Use MDN's actual [Getting started](https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started) or [Core](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core) topic as the reading companion. Do not give a giant mandatory curriculum or a time-to-employment promise.
6. Reassess after a retry and one transfer task. Advance the observed concept when the learner can make the small change and explain its effect; record hints used. If evidence is mixed, reduce the next exercise rather than lowering an identity label.
7. Return a short record: recommended topic, baseline evidence, next action and understanding status. Route non-web language learning to an actual selected specialist or disclose the gap. A web fundamentals manual is not a Rust, Swift or backend curriculum.

Grounding: [L01-L04 and teaching policy](../references/research/distilled-project-learning.md). These routing rules are authored policy, not a validated scoring scale. There is no universal pass percentage.
