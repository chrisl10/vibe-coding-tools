# Review a lesson's evidence

Report what the learner did and what was actually checked.

1. Read the learner's real attempt and prior hints. If none exists, mark understanding PENDING. Do not convert a generated answer, satisfied user acknowledgment or passing syntax check into learner competence.
2. Compare the exact attempted behavior with the lesson card. Distinguish a correct prediction, a working change, an explanation in the learner's words and transfer to one changed requirement. Record each separately. One demonstration supports that concept in that setting, not general mastery.
3. Ask one teach-back question: “What changes when you press the button, and which line makes that happen?” Accept the learner's language and correct only material misunderstanding. Do not shame uncertain answers or judge grammar.
4. Record execution evidence precisely. Syntax parsing supports syntax. A synthetic document stub supports the checked handler transitions. A real browser observation supports the tested interactions. Keyboard focus, zoom and screen reader output each need their own observations.
5. Give one next exercise from the remaining gap. If the learner asks for dates, paid courses or cost estimates, route to the actual selected decision owner and use current sources. Do not guarantee completion from hours per day.
6. Save a record only with current authorization. Avoid private code, credentials, customer data, grades or learner profiles in external tools. The lesson has no need for them.
