# Choose a first representative slice

1. Select ONE small behavior that resembles the important product risk: one user's input, meaningful action/output and failure/denial. Do not choose a decorative homepage to qualify an integration's authorization path.
2. Keep the slice a proposal with acceptance evidence and owner, not application code. Use fictional/test data where appropriate and record missing permissions; do not access live accounts/data.
3. Identify the learning prerequisites for that behavior: reading an error, explaining request/data/access flow or reviewing a change. Avoid a blanket demand to learn every language/provider first.
4. Preserve deferred features and one trigger for adding them. Keep platform-specific unknowns: device persistence for native, authorization/retries for integration, public content/navigation for website.
5. Hand the slice to the actual selected implementation owner only with accepted scope/action authority. This readiness workflow does not scaffold, install or execute it.
