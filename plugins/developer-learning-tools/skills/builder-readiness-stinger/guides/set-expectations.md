# Explain what to expect and what the owner does

1. Start with the known product outcome. Explain the difference between learning sample, prototype, pilot and production using the role/readiness reference; these are workflow distinctions, not formal certifications.
2. Use grade-8 language and one bounded workshop analogy if useful. Define unfamiliar words near first use; keep the real software explanation alongside the analogy.
3. Explain that AI drafting still needs inspection/testing and that learning/rework/failure handling consume effort. Do not invent a universal AI multiplier, completion date, tool spend or adoption statistic.
4. Name product decisions, implementation, security/quality review and support/recovery ownership. For paid users, preserve data/access/payment/operations unknowns instead of declaring the app ready.
5. Ask one teach-back question: "To check that I explained this clearly, what will you decide, what can AI help draft, and what evidence will you want before real users rely on it?" Mark understanding pending until a response provides evidence.
