# Interview the goal without overwhelming the learner

1. Read supplied context and identify the product shape and desired milestone. Ask only unresolved user/problem, platform, must-have behavior, existing experience, data/permissions and budget/time constraints that change the recommendation.
2. Use plain questions: "Who will use this, and what should they be able to finish?" "Is this a learning demo or something people will pay to use?" "What have you already built or edited?" Give one recommended answer only when the supplied situation supports it.
3. Preserve unknowns; do not translate "an app" into a full SaaS with login/payments/store membership. A missing platform can block platform-dependent work while independent glossary/context explanation proceeds.
4. Fill the readiness worksheet with reported versus observed experience and exact missing decisions. Do not collect credentials, identity documents or live user data.
5. Return a compact question batch and continue only independent advisory work. When all material inputs exist, move to one representative slice rather than asking a new generic questionnaire.
