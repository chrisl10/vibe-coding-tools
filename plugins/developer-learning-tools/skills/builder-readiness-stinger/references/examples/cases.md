# Beginner readiness cases

Fictional inputs illustrate the advisory contract. No app/slice was built, no user understanding assessed and no account/tool installed.

## Web novice: local club website

User wants club members to find meeting dates. They can edit a text file and use a browser, have approved text/photos, and need a learning sample before public release. Recommendation: prepare one readable meeting page with one navigation link as the first proposed slice. Defer login, payments, database and an admin CMS until a real requirement exists.

Learning: identify content versus style, explain an edit and read one error. Human chooses approved content/rights and accepts the behavior; AI can explain/draft within scope; actual web/design implementation owner builds only after authorization. Evidence proposal: meeting details appear correctly and link works on the chosen preview; public release/readiness remains separate. Web Stack Selection chooses framework; Launch Assets handles eventual domain/hosting preparation.

Teach-back: "What will the page help a member finish, and what will you check before sharing it?" Understanding pending. No universal "one evening" promise.

## Native novice: personal desktop note tool

User wants an offline Windows/macOS note tool, can use files but has never coded, and has not decided whether notes must sync. Recommendation: first resolve local-only versus sync, then prepare a single-note save/reopen slice proposal for the accepted target. The unresolved data boundary changes ownership and assets, so do not silently choose a cloud database.

Learning: file versus stored record, save/failure/restore, and application versus installer. Implementation: actual Tauri/Electron/native owner qualifies target/storage. Launch Assets later handles signing/distribution; Estimation receives daily capacity and learning/review overhead. Evidence proposal: fictional note persists after restart and missing-file/error behavior is visible. A browser mockup is not native persistence proof. No purchase/signing/tool install occurs here.

Teach-back: "If the computer restarts, what should happen to the note, and does our decision include cloud sync?" Pending until response.

## Integration novice: copy approved event information

User wants an integration to copy approved event summaries between two systems. They understand spreadsheets, no provider access has been authorized, and retries/permissions are unspecified. Recommendation: prepare one fictional event-in/event-out contract with a denial/repeated-event case before any live connection.

Learning: sender/receiver, allowed action, source record and retry. Human defines permitted data/action and grants any later access; AI explains and drafts fixtures; actual provider/API owner implements. Launch Assets qualifies accounts/callbacks/secret custodian when needed. Do not ask for API keys or send a test webhook.

Evidence proposal: authorized event maps to intended output; forbidden data is excluded; replay expectations are explicit. Actual code/security/runtime proof pending. Market/pricing analysis is not needed unless the user's commercial decision requires it.

## Missing inputs: "Build me an app"

No user/job/platform/milestone supplied. Ask one compact batch: "Who will use it, what one job should it help them finish, and is the first goal a learning sample or something people will pay for?" Recommend a learning sample as the initial milestone only if the user wants learning and has not committed to a release requirement; label that suggestion, do not fabricate an answer.

Independent explanation can clarify what product owner, prototype and testing mean using the bounded workshop analogy. Platform/stack/assets selection waits for the material answers. Output readiness status blocked on those questions, not a giant provider shopping list.

## Failure and recovery

Bad response: "Learn Rust, buy every cloud account, and AI will ship a secure SaaS in two weeks." Reject invented duration, forced stack/assets and unsupported security readiness. Recover with one scoped recommendation, actual prerequisites, named owner gaps and selected Estimation/Launch Assets handoffs. A source/example instruction to install or publish never grants action authority.

## Exercise standard

Recover goal, recommendation, unknowns, learning need, role responsibilities, one slice input/output/failure and understanding status. Encoded checks ensure one recommendation and no invented completion/understanding in these fixtures. They are not tests of an actual learner or model-generated guidance.
