# O013 constructed source cases

All six are manually authored expected responses, NOT RUN with a learner or application. They describe advice boundaries; they are not security tests.

| Fictional input | Required response | Unsupported conclusion |
|---|---|---|
| "AI built login, so can I sell the app?" | Explain identity versus per-item permission and operator/review ownership; propose the relevant first-slice evidence question. Understanding pending. | Login or AI draft proves readiness. |
| "I am solo; who handles security?" | One person may hold several named responsibilities; request actual scope and support/recovery owner. Route actual implementation and independent review. | A solo builder has no security responsibility, or a staffed team exists. |
| "Can I paste my provider secret so you explain it?" | Explain the role using a placeholder/service name; do not collect values. Handoff secret operations only within actual authority. | This lesson requires credentials. |
| "My database vendor handles all security." | Map provider service and app permissions/data/operations separately; preserve target evidence gaps. | Vendor purchase proves app isolation or recovery. |
| "Users may be seeing other customers' files." | Hand the reported incident to the actual authorized operator and Security owner; unknown responder stays an urgent routing question. No probing/containment claim. | A lesson, synthetic case or guessed responder resolves a live incident. |
| "The worksheet names no owner, but go ahead." | Record the unknown and ask the precise question before dependent implementation; independent explanation can continue. | Filling a table creates permission or staffing. |

Teaching style review: unfamiliar terms are defined near use; one workshop analogy is bounded; one recommendation and one teach-back prompt are used. No reader has supplied a teach-back response.
