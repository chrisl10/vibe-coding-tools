# Model and review

1. Start from [the input template](../references/templates/input.json). Replace its fictional assumptions with supplied values and provenance. Build baseline, high-usage and downside scenarios. Give each scenario a complete field set and separate source notes in the [worksheet](../references/templates/worksheet.md).
2. Run the local calculator from the skill directory: `python3 -m scripts.calculate --input references/templates/input.json`. It reads only that explicit file and emits JSON to stdout. No output path, remote URL or provider call is supported. See [script instructions](../scripts/README.md).
3. Reconcile gross collected revenue, refunds, fee returns, fees, fixed costs and variable costs against [the formula contract](../references/model.md). Keep money amounts, per-unit amounts and ratios labeled. Basis: [SBA](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/software-economics-tools/skills/unit-economics-stinger/references/research/raw/sba-break-even.txt), [Stripe](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/software-economics-tools/skills/unit-economics-stinger/references/research/raw/stripe-refunds.txt).
4. Review contribution and gross profit separately. Payment fee and delivery cost classification changes gross margin; behavior changes contribution and break-even. Do not rename modeled operating surplus as after-tax net profit or cash flow. Basis: [American Express](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/software-economics-tools/skills/unit-economics-stinger/references/research/raw/amex-gross-margin.txt).
5. Show loss-making volume and impossible break-even plainly. If contribution is nonpositive, volume alone cannot cover positive fixed costs under this model. Round required whole units upward. Basis: [SBA](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/software-economics-tools/skills/unit-economics-stinger/references/research/raw/sba-break-even.txt).
6. Recommend the highest-impact assumption to verify, naming its evidence and the sensitivity result. Output the reviewable worksheet, input JSON, resulting JSON, model limitations, and questions. Do not enact rate changes, customer charges or provider configuration.
7. Resolve downstream owners through Core's selected-owner resolver before loading them. Payments owns accepted billing implementation. Estimation owns delivery forecasting. Infrastructure costs need the appropriate selected platform owner. If unavailable, report the missing owner rather than treating a cached sibling as selected.
