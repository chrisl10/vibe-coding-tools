# Maintain the scope boundary

Use the [maintenance worksheet](../references/templates/maintenance.md) to separate recurring service from the project quote. List included task types, volume/hour caps, support window, response target versus resolution target, security/dependency work, backups/recovery verification, hosting payer, reporting and excluded new features. Do not promise unlimited support from an average-hours calculation. Define incident and overflow handling before proposing a retainer. One-time onboarding and monthly coverage use separate periods. Expense basis.

Use [change request](../references/templates/change-request.md) for changed pages, revised design rounds, new roles, API substitutions or discovered migration work. Record the accepted baseline and requested delta. Estimate only additional non-overlapping work, validate which existing costs remain, reprice the delta with stated method, and show old/new totals and schedule impact. Do not silently consume contingency to fund unrelated features or start changed work without owner/counterparty decisions through their process.

Example: an accepted five-page website gains two pages and a second revision round. The additional effort is repriced as its own proposal; the old quote and accepted scope stay intact. If a previously unknown integration invalidates the estimate, stop the affected fixed-price conclusion and propose bounded discovery, retaining all assumptions that failed. Resolve Estimation again when delivery assumptions change; resolve legal help before representations about enforceability, IP, warranty, tax or cancellation.
