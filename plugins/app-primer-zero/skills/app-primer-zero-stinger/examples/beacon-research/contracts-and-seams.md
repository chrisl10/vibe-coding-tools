# Beacon Research proposed interfaces

> Fictional boundary map | Two Draft revision-1 contracts | No acceptance evidence

These abbreviated examples teach preparation. A real CTR uses the installed Contract Writing template and all mandatory fields. No terms are accepted by this example.

| Contract | Producer | Consumers | Input/output and refusal | Critical seam |
|---|---|---|---|---|
| CTR-001-intake r1 Draft | Intake/data owner | Interface and processing owner | Scoped member, validated request and exact request key; reject wrong scope or changed replay digest | Input to durable admission |
| CTR-002-evidence r1 Draft | Evidence/processing owner | Brief interface and artifact reader | Captured source set and exact current brief version/hash; reject unsupported claims, stale versions or failed outputs | Evidence to cited output/readiness |

The actual design still needs decisions about data lifetime, processing retries, unknown outcomes and readiness. No provider, model or database is prescribed. Producer and consumer share the exact accepted revision before either can claim implementation readiness.
