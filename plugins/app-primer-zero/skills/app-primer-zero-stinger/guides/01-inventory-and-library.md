# Inventory the app and organize its Library

Use Get Started for baseline setup inside the authorized scope. Respect the user's CI preference; do not add CI when deferred. Inventory existing configs, manifests, dependencies, lockfile, source, routes, workers, schema, tests, prototypes, provider adapters and documentation. State which are specified, present, runnable, exercised or deployed with dated evidence. A package script pointing at a missing file is not implemented behavior.

Use Knowledge for narrative current state and Library for PRD wrappers/lifecycle. Preserve the core ownership split. Put architecture, data, integrations, frontend, operations, standards and roadmap material in private domains as needed. Keep human notes human-only. Do not put source/binary brand assets or generated customer deliverables in the knowledge tree.

Organize existing docs only when moving/splitting/renaming is explicitly within the user's scope. Preserve source bodies and record old path, new part, source SHA/hash and line ranges in a migration ledger. Update real Markdown destinations, not text that happens to resemble a path in a code block. Never label contradictory historical prose as a newly accepted decision. Leave files owned by an active worker untouched and request the narrow ownership transfer where needed.

Produce a state-of-the-union document with current behavior, missing implementation, reusable pieces, known failures, selected decisions and next blocking seam. Report exact results instead of extrapolating from another app's tests. Run only necessary authorized checks. Existing toolchain failures are quoted with sensitive values removed; don't install a replacement to hide the failure.

The [schema ledger](../templates/schema-ledger.md) and [decision ledger](../templates/decisions.md) connect inventory to the next phase. Provider defaults are not inferred from the example.

Grounding: core Get Started/Knowledge/Library responsibilities in the first-party workflow note (source archive, summarized in the distillation); detailed current rules remain in the installed core skills.
