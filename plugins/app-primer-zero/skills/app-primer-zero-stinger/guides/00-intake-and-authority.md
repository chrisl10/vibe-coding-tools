# Establish scope and authority

Read the user's current request, repository instructions and already approved decisions. Resolve only the missing choices that change dependent work: target repository, allowed document organization, provider stack, preparation versus implementation scope, CI preference, harness/model/concurrency, and source repositories allowed for reuse. One compact question batch is sufficient; continue independent inventory while waiting.

Record the full base SHA, branch, dirty files and active worktrees, or state that a supplied archive has no Git identity. Identify active owners before touching shared files. Preparation authorization permits the requested artifacts; it does not imply deployment, credential entry, live provider writes, installation, paid API execution or external messaging. Carry existing specific approvals forward without demanding repetition or broadening them.

Read the installed core methods using the [dependency resolver](../references/core-dependencies.md). Core metadata is not proof that a callable Drone, browser, shell, database or threaded agent capability exists. Inspect the active harness's native capabilities and report the effective model/limit. Any user-supplied concurrency limit remains unverified until qualified. The official [ZCode changelog](https://www.zcode.network/en/changelog/) supports model availability, not a particular installed concurrency limit.

Separate preparation from implementation: draft interfaces and plan future chips now; do not launch implementation workers just because a wave plan names them. Use helpers only when delegation is authorized and their file/read-only scope is explicit. Without native helpers, perform preparation serially and use the explicit `serial-preparation` capacity mode in a JSON handoff. It cannot claim independently reviewed implementation readiness.

Track actual clock and effective deadline. Follow the controlling user's cadence, retries and stops. Do not claim a hook, watchdog or timer enforces them unless configured and tested. Preserve saved artifacts and return a concrete checkpoint when blocked.

Grounding: current first-party workflow evidence (source archive, summarized in the distillation) and ZCode observation (source archive, summarized in the distillation) in source; packaged distillation carries the source URLs.
