# App Primer Zero workflow map

Use this skill to prepare a new or partial repository for a subsequent build. The reader is the coordinator taking over that repository, not a runtime customer.

| Phase | Method and owned output | Guide |
|---|---|---|
| 0 | Intake, authorization record and truthful baseline | [Intake](guides/00-intake-and-authority.md) |
| 1 | Get Started and private Knowledge organization | [Inventory and Library](guides/01-inventory-and-library.md) |
| 2 | Exact contracts, critical seams, foundation PRD and schema | [Contracts and schema](guides/02-contracts-and-schema.md) |
| 3 | Pinned reuse and dependency-ordered implementation handoff | [Reuse and waves](guides/03-reuse-and-waves.md) |
| 4 | Structural review, Security then Quality, final handoff | [Verification](guides/04-verification-and-delivery.md) |

Core specialist methods are resolved through [core dependencies](references/core-dependencies.md). Repository packaging and harness entry points are documented in [threading](references/threading.md). Read [distilled grounding](references/research/distilled-app-primer-zero.md) when a capability claim is disputed.

Use the [foundation PRD scaffold](templates/foundation-prd.md), [decision ledger](templates/decisions.md), [schema coverage ledger](templates/schema-ledger.md), [reuse ledger](templates/reuse-ledger.md), [wave handoff](templates/wave-handoff.md), and [worker assignment](templates/worker-brief.md). The [fictional Beacon example](examples/beacon-research/README.md) demonstrates the output boundaries. The JSON validator checks structural planning mistakes, not runtime conformance or actual user approval. Read [capacity and review](references/capacity-and-review.md) for small parallel plans and one-slot serial preparation.
