# Projection consistency, evaluation and exit

Grounding: primary digest. No two-store atomicity is assumed.

1. Define authoritative records, projection id/version/model stamp, accepted event/CDC/outbox source, ordering, deduplication, retries, deletion tombstones, tenant/visibility updates and reconciliation. Contract-writing-stinger drafts shared provider/consumer agreements; Library pins their exact accepted revisions. No guessed backfill, implicit dual-write atomicity or assigning retained records to a tenant by inference.
2. Define visible consistency semantics: when a write is searchable, what acknowledgement means, stale-result handling, deletion/revocation deadline and permitted read failures. Qdrant consistency/read/write-ordering controls are separate knobs; use official current behavior and measured tests. A completed local vector write does not prove the authoritative relational transaction and projection are synchronized.
3. Build golden cases with retrieval owner: known-id match, paraphrase, no match, highly selective tenant filter, many tied neighbors, null/missing embedding, text/image modality mismatch, duplicate events, delete-before-late-update and a membership revocation. Security reviews exclusion of inaccessible content before snippets/counts/results are exposed. Retrieval grades relevance; vector-store grades store/operator/index and consistency behavior.
4. Benchmark the approved isolated test fixture under both read and write/backfill pressure. Preserve source snapshots and configurations, exact metric definitions and run artifacts. Report each missing measurement. A pure no-filter benchmark cannot qualify production tenant-filtered recall; a browser mock cannot qualify storage durability or cluster recovery.
5. Before migration, draft additive new projection/index collection, verified ingest/reconcile ledger, shadow comparison, accepted cutover trigger, rollback and authorized cleanup. Export/import vectors, payloads and authoritative version mappings with access rules intact. Actual database creation, paid traffic, provider changes, backfill, destructive cleanup and deployment require applicable explicit authorization.
6. Deliver the [decision record](../templates/vector-store-fit-decision.md), exact provider/consumer contract pins, gold-query/evaluation paths, consistency/deletion denial cases, incomplete evidence and owner assignments. Existing indexes/migration scripts remain with their original implementation owners. Implementation gates run Security, Quality, then orchestrator Repository Health.
