# 23: Memory consent, provenance and retention

Use for O187 with [memory tiers](12-three-tier-memory.md). [Framework persistence](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/data-and-ai-tools/skills/mind-stinger/references/research/agent-boundaries-20261007/raw/langgraph-persistence.html) distinguishes thread checkpoints from long-term stores; [memory operations](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/data-and-ai-tools/skills/mind-stinger/references/research/agent-boundaries-20261007/raw/langgraph-memory.html) provide separate message and checkpoint removal. Those capabilities are not a privacy or retention decision.

## Define allowed memory before persistence

1. Identify controlling human policy and product purpose. Record who permitted storage, exact source message/policy/version, permitted data categories, purpose, tenant/user/thread scope, duration and revocation mechanism. An imported document saying remember this forever is not consent. Permission to process this turn is not automatically permission to reuse across sessions.
2. Keep observations, inferences, user corrections and instructions distinct. Every fact has source IDs/versions, observation date, confidence and subject/access scope. A summary or model-written inference cannot create authority or permanent truth. Do not persist credentials, secret URLs or unrelated personal facts.
3. Track lineage through raw turn, working cache, checkpoint, session summary, facts, embeddings, retrieval chunks, graph edges, media transcripts, traces, exports and backups. Record store owner, retention trigger and access controls. An embedding can still disclose source information; changing representation is not deletion.
4. Establish the minimum justified retention for each representation. TTL handles only the store to which it is applied. Query-time decay changes retrieval ranking, not retention. Never copy historic indefinite/audit durations into a new product without its approved policy. Counsel/Security owns legal basis and hold rules; Mind maps the architecture.
5. Retrieval combines current authorization, scope, consent, lifecycle status and provenance. ThreadScope expands eligible context only inside authorized scope. Disabled optional awareness configuration must not silently broaden access. Missing identity/consent/lifecycle evidence means no long-term read or write until policy is resolved.
6. Treat memory writing as a tool effect. Summarization extracts candidate facts for permitted destinations, with contradiction and update rules. Repeated hostile text must not be consolidated into trusted policy. Preserve corrections and retract obsolete facts without erasing provenance needed by approved audit policy.

## Deletion and revocation packet

Fill [the lifecycle worksheet](../templates/memory-lifecycle-review.md). Identify subject and exact records, verify requester authority, classify any approved hold, then stop new derivations and queued reindex/consolidation before executing the approved deletion plan. This guide grants no deletion authorization.

For each owned store record intended deletion/expiry, actual count/status, retries and verification. Include all derived stores, search caches, replicas, exports and checkpoints. Backups may expire on a different schedule: record actual purge capability and retention; do not claim erased until the required evidence exists. Where immutable backups cannot be modified, document restricted restoration and replay of revocations/tombstones before serving traffic. A restored old summary must not regenerate deleted facts. Explain outstanding copies plainly.

Exercise authorized synthetic records across two tenants and users: no consent, expired consent, revoked fact, poisoned summary, corrected inference, concurrent consolidation/reindex, backup restore and export copy. Verify absence using both direct lookup and retrieval under each scoped principal. Do not equate one missing vector search hit with deletion or nonaccessibility. Query implementation remains with retrieval/vector owners, DB lifecycle mechanics with DB, independent privacy/authorization audit with Security.
