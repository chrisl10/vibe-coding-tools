# Qualify a local model against the actual machine and workload

Use this for “will a local model fit?”, “what hardware do I need?” or “can this run offline?”. Read [the current digest](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/data-and-ai-tools/skills/ai-tools-platform-stinger/references/research/request-budgets/digest.md), then fill [the fit worksheet](../templates/local-model-fit.md). Do not guess the user's device or recommend a purchase from parameter count alone.

1. Collect intended task, output quality rubric, latency/throughput target, input/output/context lengths, simultaneous requests and simultaneously loaded models. Separate interactive development from production serving. An open-weight license does not mean zero operating cost or universal redistribution permission.
2. Collect supplied hardware evidence: machine/CPU architecture, OS version, physical and presently available RAM, unified versus separate GPU memory, exact GPU(s), VRAM/free VRAM, driver/backend versions, supported instructions and storage space. Capture measured load/other-process headroom only when authorized; do not run probes or invent it in a source-only exercise. Check current runtime OS/GPU eligibility first.
3. Identify publisher card and exact candidate version/revision. Identify the actual file/artifact and its checksum or runtime digest, bytes, weight quantization, tokenizer/chat template, context limit, KV-cache format and runtime version/backend. A tag such as “latest” or a card URL is insufficient artifact identity. A source-only candidate without downloaded bytes has Unknown artifact hash and cannot claim installed fit. Review license and commercial/distribution restrictions with the appropriate owner.
4. Account separately for weights, KV cache at required context/concurrency, runtime buffers, graph/backend overhead, other loaded models and OS/application headroom. Disk bytes do not equal total memory. Do not add separate RAM and VRAM as universally interchangeable; partial offload changes performance and compatibility. Ollama documents parallel-request context memory growth; verify actual allocation rather than multiplying a universal GB-per-billion rule. Preserve failure if a required backend/driver is unsupported.
5. Preserve exact runtime context settings and observed CPU/GPU split when supplied. Current Ollama context and FAQ pages differ on default description; version and allocated context are required evidence. Do not universally set 64K just because a task involves code. Choose the minimum task-adequate context, then verify its effect on quality and memory. Runtime “OpenAI-compatible” labels still need endpoint, tools/structured-output/stream/error compatibility evidence.
6. Propose an owner-approved benchmark before purchase/deployment: sanitized representative inputs, immutable artifact/runtime/settings, cold-load and warm runs, concurrency sweep, sample count, time to first token, output tokens/sec, p50/p95 end-to-end latency, peak RAM/VRAM, errors/OOM and quality failures. Retain run date/method/raw metrics and power/thermal/background-load conditions. No benchmark ran in this update. Unsupported or unmeasured fit is conditional, not a pass.
7. Review complete egress: local/cloud routing, remote fallback, web search/tools, embeddings, telemetry, logs, model fetch/update paths, bind address and remote clients. Ollama local-only controls address its cloud features, not every plugin. Private cloud/VPC is a separate deployment with provider/network controls to verify. Security owns secrets, network/retention and independent privacy acceptance.
8. Include hardware amortization, electricity, support/time, availability and capacity in the cost comparison. Reuse Software Economics worksheets with supplied rates and disclosed amortization allocation; do not create another calculator or promise “free” inference. End with supported / conditional / unsupported and exact evidence that would change the decision. Re-evaluate on artifact/runtime/OS/driver/context/concurrency or quality changes.

See [the local-fit cases](../examples/local-model-fit-cases.md). These classify source evidence, not the owner's machine or a model benchmark.
