# /prepare-assets

## Mandatory process

1. Load the installed `pest-controller-suit` Core skill and consult its roster before making any routing decision. This is the first instruction, always, no exceptions. Resolve Core using the host skill resolver or explicit selected-plugin registry; source checkout work uses the root catalog's Core source root. Missing Core blocks routing.
2. Resolve `launch-assets-stinger` from selected `infrastructure-decision-tools` for the `prepare-assets` workflow and read its root/guide map. Confirm product type, platforms, intended users, payments, release route, accountable owner, existing assets and authorized read/output scope only where unresolved.
3. Dispatch `launch-assets-wasp-drone` at top level when its registered role is exposed and delegation is authorized. Arm it with its paired Stinger and exact source/output boundary. Otherwise read the paired agent and use the Stinger directly, reporting direct use rather than native dispatch.
4. Research current official requirements and populate a platform-specific editable ledger. Separate environments, public requirement evidence, owner reports and authorized observations. Every cost carries amount/unit/currency/source/date or remains unknown. Lead times need sourced/estimated basis or remain unknown.
5. Review minimum assets, missing prerequisites, blocking evidence and deferred vendors. Keep TLS separate from executable signing; no EV SmartScreen bypass promise. Missing optional specialists produce precise handoff gaps, not invented setup instructions.
6. Return editable rows, immediate blockers, deferred assets with triggers and selected-owner next actions. Save only to the user's authorized output scope when writing tools are available. Never create accounts, access credentials, change provider settings, spend, install, deploy, publish, send or commit through this preparation command.
