# /choose-infrastructure

## Mandatory process

1. Load the installed `pest-controller-suit` Core skill and consult its roster before making any routing decision. This is the first instruction, always, no exceptions. Resolve Core via host skill resolver or explicit selected-plugin registry; source checkout work uses catalog source roots. Missing Core blocks routing.
2. Resolve selected `infrastructure-fit-stinger` from infrastructure-decision-tools for this workflow, then read its guide map. A staging draft is not a registered installed role. Confirm workload/lifecycle, data, users/regions, budget, operator skills and recovery constraints only where missing.
3. Dispatch infrastructure-fit-wasp-drone at top level only when its registered role exists and delegation is authorized; arm its paired Stinger and exact scope. Otherwise read the paired agent and execute the workflow directly, truthfully reporting direct use.
4. Normalize one workload for every eligible candidate. Compare managed hosting/container services and VPS using current official plan/runtime/region evidence. Treat user concerns about vendor price/complexity as constraints to test, not universal facts.
5. Assign app/data/network/backup/security/support duties and defer unnecessary layers. Resolve selected Operating Cost for dated rate inputs and low/base/high model output; missing capability/rates means totals unresolved. Do not duplicate calculators.
6. Deliver ONE sourced or explicitly provisional topology recommendation, decisive fit, evidence blockers, operator duties, recovery/exit and reassessment triggers. No unsupported price/latency/SLA/region claim and no automatic accounts, credentials, provisioning, settings, spend, installation, deployment, publication or commits.
