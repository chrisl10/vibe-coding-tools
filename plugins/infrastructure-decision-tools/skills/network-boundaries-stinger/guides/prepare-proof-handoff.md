# Prepare the owner and proof handoff

1. Use the [worksheet](../references/templates/flow-control-worksheet.md) to state each control's normal behavior, outage mode, bypass route, recovery/rollback authority and user-visible response. Do not prescribe global fail-open or fail-closed behavior: paid mutation, public read, operator recovery and telemetry may need different risk/availability decisions. Unknown owner decision blocks an executable proposal.
2. Ask for actual request-rate distribution and legitimate bursts, shared-NAT/client behavior, webhook retries, scheduled jobs and concurrent sessions. No guessed requests-per-minute limit. Preserve expected rejected-work cost, edge inspection charges, downstream/provider work already started, retry amplification and billing evidence as UNKNOWN when unavailable. Resolve Operating Cost for arithmetic, not a new calculator.
3. Define target-specific negative proof: direct origin/alternate ingress, forged forwarding headers, wrong authenticated tenant, unauthenticated admin access, IPv6, long-lived/non-HTTP traffic, legitimate burst, over-limit expensive action, retry duplication, counter/storage outage and return-path behavior. Security owns risk coverage; runtime owners execute only with authorization. Expected outcomes are not execution receipts.
4. Resolve selected Core Security for threat and authorization review; selected Vercel for Vercel attachment/limits, Tailscale for tailnet policies, and the actual app language/runtime owner for admission/identity. Use trusted Core's selected registry on installed hosts. Cached siblings or source presence do not prove selected roles. AWS/Cloudflare/OS firewall implementation without a declared selected specialist is a precise OWNER_GAP, not a guessed substitute. Selected DevOps may review generic container/CI aspects within its stated scope; that does not make it a cloud firewall implementation owner.
5. Return the recommendation and handoff in chat; the orchestrator may save an authorized artifact. Include target/revision, source/fetch dates, provisional/ready status, unresolved decisions, owners, rollback proposal and NOT_RUN proof rows. No account, credentials, rules, firewall/WAF/ACL/settings change, scan/attack, install or provider API write occurs.

Grounding: [counter lag and plan](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/network-boundaries-stinger/references/research/raw/cloudflare-rate-limits.txt), [instances](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/network-boundaries-stinger/references/research/raw/aws-waf-rates.txt), [proxy](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/network-boundaries-stinger/references/research/raw/express-trusted-proxies.txt), [tailnet](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/network-boundaries-stinger/references/research/raw/tailscale-acls.txt). Failure choices, authority and acceptance scenarios are derived workflow policy.
