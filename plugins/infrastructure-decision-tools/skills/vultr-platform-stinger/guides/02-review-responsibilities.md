# Review data, network and recovery responsibilities

1. Map every persisted asset to local instance disk, attached block volume, object bucket or managed database. Local/attached block storage and object storage have different access semantics; do not treat object storage as a filesystem or DB. Record capacity, I/O assumptions, growth, region, access, retention and deletion needs separately. [Block](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/block-storage.html), [Object billing](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/object-storage.html).
2. Give the customer an explicit VM duty list: OS/application patches, authenticated administration, host and provider firewall policy, TLS, secret handling, logs/alerts, incident response, capacity, application-consistent exports and restore verification. Provider infrastructure features do not certify the customer application. Managed DB provisioning/maintenance reduces the server duty surface while schemas, users, application authorization and recovery acceptance remain customer decisions. [Security](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/security.html), [Engines](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/database-engines.html).
3. Plan public/private exposure, trusted callers, egress and same-region dependencies from exact service documentation. VPC must not be assumed to encrypt traffic, establish application authorization or provide cross-region connectivity. The archived VPC overview is a catalog shell; leave its topology eligibility unresolved and retrieve an actual article before relying on it. [VPC fetch](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/vpc.html).
4. Separate manual instance snapshots from scheduled Automatic Backups and application-consistent backups. Automatic Backups exclude attached Block Storage. Bare Metal does not support instance snapshots. Block Storage's overview advertises its own snapshots but the FAQ body visible in this archive does not resolve every limit or supported combination. Require a separately supported volume recovery strategy. [Backups exclusion](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/backups.html), [Bare Metal limit](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/bare-metal-snapshot.html), [Block](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/block-storage.html).
5. Map RPO/RTO to exact managed DB plan/engine eligibility. PostgreSQL's FAQ gives PITR history Premium 30 days, Business 14, Startup 2, Hobbyist none; Valkey lacks PITR. Availability of backup functionality cannot prove recovery time or zero data loss. [PostgreSQL](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/postgresql.html), [Valkey](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/valkey.html).
6. Record failure domain, off-provider copy/export, encryption/key custody, retention, restore destination, application consistency, recovery order and owner. Database encrypted backups are documented in the same region as the service; this does not prove independent regional disaster recovery. [Encryption](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/database-encryption.html).
7. Prepare an exit/recovery rehearsal proposal, with test inputs and acceptance criteria, for the selected implementation owner. The portability article makes mission-critical backup the customer's responsibility and says snapshots/backups cannot be downloaded directly; a temporary instance is described for recovering data. Any such provisioning, export, restore, deletion or charge requires separate explicit authority and is not performed by this specialist. [Portability](https://github.com/legioncodeinc/the-wasp-nest-source/blob/main/packs/infrastructure-decision-tools/skills/vultr-platform-stinger/references/research/raw/portability.html).
