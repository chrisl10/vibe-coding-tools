# DigitalOcean fit digest

Captured 2026-10-07. Ledger records URL, UTC fetch, body/file SHA-256 and failures. These are public service descriptions and rates, not a quote for a customer, workload benchmark, available account capacity, compliance approval or runtime proof.

| Decision | Grounded discriminator | Raw evidence |
|---|---|---|
| App compute | App Platform accepts repository/container deployment and separate service/worker components. Local state is discarded when containers are replaced; volumes are unsupported. Externalize durable data. | limits, storage, workers |
| Runtime | Validate AMD64 binaries and required syscall compatibility. App Platform documents gVisor restrictions, unavailable SMTP ports, and unsupported gRPC over HTTP/2. Networking text contains overlapping HTTP/2 descriptions; do not promise protocol behavior without current exact documentation and an eventual workload probe. | limits |
| Scaling | The pricing table labels dedicated CPU autoscaling. The limits page distinguishes CPU scaling from request scaling, with request scaling eligible for external HTTP services on shared or dedicated CPU, excluding workers. Preserve mode/plan eligibility instead of converting either source into a universal scaling claim. | pricing, limits, scaling |
| Region | App availability is a generated product/region table dated 7 Oct 2026. DB, VM, VPC, storage and any replica need their own exact region/service evidence. An available app region does not prove all service co-location, latency or residency obligations. | availability, DB limits |
| VM ownership | Droplets are Linux VMs. Operator duties include OS/runtime patching, access, firewall, app deployment, monitoring and recovery. Recommended setup provides examples, not authority to run its commands. | Droplet pricing, setup |
| Managed PostgreSQL | Maintenance, encryption and seven-day PITR are documented. HA with standby, a single node, read-only replica, and recovery are distinct. Restore requires a new node and reattachment of replicas. Data/tenant/application/security duties remain with the operator. | features, limits |
| DB edition/date | Current pricing describes $15/month 1 GiB single node, historical eligible $30/month primary plus matching $30/month standby, and Advanced from $130/month per primary with matching priced nodes. New Standard clusters lose >4 GiB and standby/read-only eligibility from 15 Oct 2026 for accounts that have never created either PostgreSQL or MySQL clusters, and 30 Nov 2026 for all accounts. Preserve account cohort/create date/edition and recapture before purchase. | pricing, limits, transition |
| Droplet billing | Bundled CPU and v5 configurations have different caps: bundled plans cap at 672 hours/month; v5 has no monthly cap. Powering off keeps compute reserved and billed. The source mentions destruction to end billing; this skill never executes destruction. | pricing |
| Backup billing | Basic weekly/daily plans add 20%/30% of Droplet cost. Usage plans use restorable-file GiB rates and cadence. A disk backup does not itself prove application consistency or achieved RPO/RTO. | backup pricing |
| Network billing | App outbound overage is $0.02/GiB in its distinct pool; Droplet outbound overage is $0.01/GiB in the applicable transfer pool. Managed DB transfer is excluded from bandwidth allowance billing. Trace actual routes and accrual; do not merge unrelated pools or assume public/IPv6 traffic is free because resources share a provider. | app pricing, VM pricing, bandwidth, DB pricing |
| Load balancing | Regional HTTP starts $12/month/node; regional network $15/month/node. Global has its own requests/domains/GB meters. A load balancer can route to healthy backends; it cannot make one backend or state dependency redundant. Size limits require benchmarks; backend certificate duties depend on termination/passthrough. | pricing, limits |

Rates are USD public documentation values at fetch time, excluding a complete customer bill, labor, tax/FX, account-specific agreement and every ancillary service. No rate is a default. Transfer units GB, GiB and TB remain as published and must be normalized explicitly by Operating Cost. Refresh eligibility, preview status, account limits, published rates and DB transition policy for the actual decision date.

The transition notice defines the first cohort by whether it has ever created a PostgreSQL or MySQL cluster, including deleted clusters, rather than account age. Existing clusters created before their cohort restriction remain eligible for the documented resize/fork/restore/node operations. Advanced shared-CPU expansion is future policy on this capture date; do not assume the existing $130 starting rate describes every future Advanced plan. Transition source.
