# Hand off cost and operational readiness

1. Fill the [worksheet](../references/templates/topology-cost-readiness.md) with service/plan/edition/region, quantities, runtime hours, actual route, units, allowance and dated source. Read [pricing distinctions](../references/research/distilled-digitalocean.md). Preserve bundled versus v5 billing, App versus Droplet pools, per-node LB, primary/standby and backup mode.
2. Resolve selected Operating Cost through trusted Core. Send rate rows, low/base/high workload assumptions, minimum/cap/credit eligibility, labor and unpriced lines. This skill does not introduce a calculator or substitute unpriced lines with zero. Billing changes, taxes/contracts, proration and customer total remain unverified until the cost owner handles them.
3. Assign recovery, patching, incident coverage, capacity observation, release/rollback, domain/TLS, networking, secrets and retention. Name owner roles, not invented people. Use source descriptions to prepare proof requests; do not claim RPO/RTO achieved or a security/compliance pass from a public product page.
4. Return topology, decisive constraint, recommendation status, cost handoff, unknowns, responsibilities and exit/review conditions. Use authorized Library destination `library/requirements/reports/digitalocean-platform/<date>-<topic>.md`; if the agent is read-only, return the content and ask the orchestrator to save at its authorized destination.
5. Resolve selected DevOps for supported container/CI work, DB for schema/pooling and Security for the actual review. Their selection does not authorize provisioning. If no separately authorized DigitalOcean implementer exists, explicitly report implementation unavailable; do not treat this advisory Drone as that owner.
